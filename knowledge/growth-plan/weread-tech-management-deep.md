## 第一部分：技术管理者角色认知

### 从 IC 到 Manager 的转变

```
个体贡献者 vs 技术管理者：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│  个体贡献者 (IC)                                                    │
│  ├── 核心价值：个人技术产出                                         │
│  ├── 成功标准：代码质量、技术方案、问题解决                          │
│  ├── 时间分配：编码 70% + 评审 20% + 沟通 10%                       │
│  └── 影响力范围：自己负责的区域                                      │
│                                                                     │
│  技术管理者 (Manager)                                               │
│  ├── 核心价值：团队整体产出                                         │
│  ├── 成功标准：团队绩效、人才培养、技术建设                          │
│  ├── 时间分配：管理 40% + 技术 30% + 沟通 30%                       │
│  └── 影响力范围：整个团队及上下游                                   │
│                                                                     │
│  关键转变：                                                         │
│  ├── 从 "我" 到 "我们"                                             │
│  ├── 从 "做事" 到 "带人"                                           │
│  ├── 从 "个人优秀" 到 "团队成功"                                    │
│  └── 从 "执行者" 到 "决策者"                                        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

│  └── 持续跟进                                                       │

技术人员成长双通道：

┌─────────────────────────────────────────────────────────────────────┐

### 导师制度

```
导师制实施框架：

├─ 导师职责：
│   ├── 技术指导：代码 review、技术方案指导
│   ├── 职业指导：成长规划、技能提升建议
│   ├── 文化传递：团队价值观、工作风格
│   └── 资源对接：跨团队协作、机会推荐
│
├─ 新人融入计划（30-60-90天）：
│   ├── 第 1 个月：熟悉环境、掌握工具、完成小任务
│   ├── 第 2 个月：独立负责模块、参与设计讨论
│   └── 第 3 个月：主导小项目、建立专业影响力
│
└─ 评估机制：
    ├── 月度 1:1 沟通
    ├── 季度成长评估
    └── 导师激励（计入绩效考核）
```

## 实践应用

### 场景 1: 新团队组建

1. **明确目标**：团队存在的价值是什么？
2. **设计架构**：组织结构设计（扁平/矩阵）
3. **招聘计划**：关键岗位招聘顺序
4. **文化塑造**：团队价值观和工作风格
5. **机制建立**：站会、评审、复盘机制

### 场景 2: 技术转型

1. **现状评估**：当前技术栈、团队能力
2. **目标设计**：转型后的技术架构
3. **路径规划**：渐进式 vs 革命式
4. **风险控制**：灰度发布、回滚方案
5. **人才培养**：培训、外部引进

## 自测题

<details>
<summary>Q1: 如何判断一个工程师是否适合转管理？</summary>

**答案**：
1. **兴趣信号**：是否享受帮助他人成长、是否喜欢协调资源
2. **能力信号**：沟通表达能力、大局观、决策能力
3. **意愿信号**：是否愿意承担更多责任、是否接受薪酬暂时不变
4. **试错建议**：先做 tech lead 试水，再决定是否转管理
</details>

<details>
<summary>Q1: 技术管理者如何保持技术敏感度？</summary>

**答案**：
1. **时间分配**：保持 20-30% 的技术时间
2. **代码实践**：亲自写代码、做 code review
3. **技术学习**：跟踪新技术、阅读技术文章
4. **团队渗透**：通过团队成员获取技术信息
5. **实战验证**：在小项目中尝试新技术
</details>

<details>
<summary>Q3: 如何处理低绩效员工？</summary>

**答案**：
1. **了解原因**：能力问题、态度问题、环境问题
2. **制定计划**：PIP（绩效改进计划），明确目标和时间节点
3. **提供支持**：培训、导师、资源倾斜
4. **持续跟进**：周会检查进展，及时调整
5. **果断决策**：改进无效时，果断调整或离职
6. **人性化处理**：尊重当事人，提供职业规划建议
</details>
