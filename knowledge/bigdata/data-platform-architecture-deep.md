# 数据中台架构深度解析

> 深入数据中台：数据采集、存储计算、数据服务、数据治理。
> 源码级分析，包含生产环境实践。
> 适用对象：数据工程师、架构师

---

## 1. 数据中台架构

### 1.1 整体架构

```
数据中台分层架构：

┌─────────────────────────────────────────────────────────────┐
│  数据应用层（Data Application）                              │
│  ├── 数据报表/BI                                            │
│  ├── 数据服务API                                           │
│  ├── 智能推荐                                               │
│  └── 数据大屏                                               │
│                           ↓                                │
│  数据服务层（Data Service）                                  │
│  ├── 统一数据服务API                                        │
│  ├── 数据目录/元数据管理                                     │
│  └── 数据权限管理                                           │
│                           ↓                                │
│  数据资产层（Data Asset）                                    │
│  ├── 数据仓库（DW）                                         │
│  ├── 数据湖（Lake）                                         │
│  ├── 数据模型（建模）                                       │
│  └── 数据质量                                               │
│                           ↓                                │
│  数据存储层（Data Storage）                                  │
│  ├── OLTP：MySQL/PostgreSQL                                 │
│  ├── OLAP：ClickHouse/SparkSQL                              │
│  ├── 数据湖：HDFS/S3/OSS                                    │
│  └── 缓存：Redis                                            │
│                           ↓                                │
│  数据采集层（Data Collection）                               │
│  ├── 日志采集（Flume/Filebeat）                             │
│  ├── 实时数据（Kafka）                                      │
│  ├── 数据同步（DataX/Flink CDC）                            │
│  └── API数据采集                                            │
└─────────────────────────────────────────────────────────────┘
```

## 2. 数据建模

### 2.1 维度建模

```
数据仓库建模方法论：

┌─────────────────────────────────────────────────────────────┐
│  Kimball 维度建模：                                          │
│  ├── 事实表（Fact Table）                                    │
│  │   ├── 事务事实表：记录业务事件                            │
│  │   ├── 周期汇总事实表：按周期汇总                          │
│  │   └── 累积快照事实表：跟踪流程状态                        │
│  │                                                           │
│  ├── 维度表（Dimension Table）                               │
│  │   ├── 角色维度：同一维度在不同场景的角色不同                │
│  │   ├── 退化维度：ID直接存在事实表中                        │
│  │   ├── 缓慢变化维（SCD）：类型1/2/3                       │
│  │   └── 合并维度：多对一关系                                │
│  │                                                           │
│  └── 星型模型 vs 雪花模型                                    │
│      ├── 星型：简单查询快，冗余多                            │
│      └── 雪花：规范减少冗余，查询复杂                        │
└─────────────────────────────────────────────────────────────┘
```

## 3. 数据质量

### 3.1 质量维度

```
数据质量评估维度：

┌─────────────────────────────────────────────────────────────┐
│  1. 完整性                                                   │
│     └── 数据是否缺失，关键字段是否完整                        │
│                                                             │
│  2. 准确性                                                   │
│     └── 数据是否准确反映业务真实情况                          │
│                                                             │
│  3. 一致性                                                   │
│     └── 不同系统间数据是否一致                                │
│                                                             │
│  4. 及时性                                                   │
│     └── 数据是否及时更新，延迟是否符合要求                    │
│                                                             │
│  5. 唯一性                                                   │
│     └── 是否存在重复数据                                      │
│                                                             │
│  6. 有效性                                                   │
│     └── 数据是否符合格式和范围要求                            │
└─────────────────────────────────────────────────────────────┘
```
