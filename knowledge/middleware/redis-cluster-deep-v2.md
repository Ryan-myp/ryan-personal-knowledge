## 1. Redis集群模式

### 1.1 架构对比

```
Redis部署模式对比：

┌─────────────────────────────────────────────────────────────┐
│  单机模式：                                                  │
│  ├── 单节点，无冗余                                          │
│  ├── 适合开发测试                                            │
│  └── 不推荐生产使用                                          │
│                                                             │
│  主从模式（Sentinel）：                                      │
│  ├── 一主多从                                                │
│  ├── 哨兵监控，自动故障转移                                   │
│  ├── 读写分离                                                │
│  └── 单Master写能力有限                                      │
│                                                             │
│  Cluster模式：                                               │
│  ├── 去中心化，16384个哈希槽                                  │
│  ├── 多Master多Slave                                         │
│  ├── 自动分片                                                │
│  ├── 支持水平扩展                                            │
│  └── 生产环境推荐                                            │
│                                                             │
│  选择建议：                                                  │
│  ├── 小流量：Sentinel                                        │
│  └── 大流量：Cluster                                         │
└─────────────────────────────────────────────────────────────┘
```

## 2. 持久化优化

### 2.1 持久化策略

```
Redis持久化策略：

┌─────────────────────────────────────────────────────────────┐
│  RDB优化：                                                   │
│  ├── 定期快照（bgsave）                                      │
│  ├── 文件紧凑，恢复快                                        │
│  ├── 适合灾难恢复                                            │
│  └── 可能丢失最后一次快照的数据                                │
│                                                             │
│  AOF优化：                                                   │
│  ├── 每秒同步（everysec）                                    │
│  ├── 数据更安全                                              │
│  ├── 文件较大，恢复慢                                        │
│  └── 适合数据安全性要求高的场景                                │
│                                                             │
│  混合持久化（Redis 4.0+）：                                  │
│  ├── AOF重写时用RDB格式                                      │
│  ├── AOF追加时用AOF格式                                      │
│  └── 兼顾速度与安全性                                        │
│                                                             │
│  配置建议：                                                  │
│  ├── save "" + appendonly yes + aof-use-rdb-preamble yes    │
│  └── 混合持久化 + 定期RDB备份                                │
└─────────────────────────────────────────────────────────────┘
```
