# 缓存架构深度解析

> 深入缓存架构：本地缓存、分布式缓存、多级缓存、一致性。
> 源码级分析，包含生产环境最佳实践。
> 适用对象：后端工程师、架构师

---

## 1. 多级缓存架构

### 1.1 架构设计

```
多级缓存架构：

┌─────────────────────────────────────────────────────────────┐
│  L1缓存（本地缓存）：                                        │
│  ├── Caffeine/Guava Cache                                   │
│  ├── 进程内，毫秒级响应                                      │
│  ├── 容量有限                                                │
│  └── 适用：热点数据                                         │
│                                                             │
│  L2缓存（分布式缓存）：                                      │
│  ├── Redis/Memcached                                        │
│  ├── 网络访问，微秒级响应                                    │
│  ├── 容量大，可横向扩展                                      │
│  └── 适用：共享数据                                         │
│                                                             │
│  L3存储（数据库）：                                          │
│  ├── MySQL/PostgreSQL                                       │
│  └── 持久化存储，最后防线                                    │
│                                                             │
│  数据流向：                                                  │
│  请求 → L1查找 → 命中返回 / 未命中 → L2查找 → 命中返回 /     │
│       未命中 → DB查询 → 写入L2 → 写入L1 → 返回               │
└─────────────────────────────────────────────────────────────┘
```

## 2. 缓存一致性

### 2.1 策略对比

```
缓存一致性策略：

┌─────────────────────────────────────────────────────────────┐
│  Cache-Aside（旁路缓存）：                                  │
│  ├── 读：缓存未命中 → 查DB → 写入缓存                       │
│  ├── 写：更新DB → 删除缓存                                   │
│  └── 最常用，实现简单                                        │
│                                                             │
│  Read-Through（读写穿透）：                                  │
│  ├── 缓存负责加载数据                                        │
│  ├── 应用只操作缓存                                          │
│  └── 需要缓存实现支持                                        │
│                                                             │
│  Write-Through（写穿透）：                                   │
│  ├── 写操作同时更新缓存和DB                                  │
│  ├── 缓存与DB一致                                           │
│  └── 写入延迟高                                              │
│                                                             │
│  Write-Behind（异步写回）：                                  │
│  ├── 只更新缓存，异步写DB                                    │
│  ├── 写入速度快                                              │
│  └── 可能丢失数据                                            │
└─────────────────────────────────────────────────────────────┘
```

## 3. 自测题

### 3.1 单选题

1. Cache-Aside策略中，写操作时应该：
   A. 先写缓存再写DB  B. 先写DB再删除缓存  C. 只写缓存  D. 只写DB
   答案：B
