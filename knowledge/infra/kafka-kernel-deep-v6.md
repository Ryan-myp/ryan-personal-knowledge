## 1. 存储引擎

### 1.1 Log Segment

```
Kafka 存储结构：

┌─────────────────────────────────────────────────────────────┐
│  Topic: my-topic                                            │
│  ├── Partition 0                                           │
│  │   ├── 00000000000000000000.log    (offset 0-999)        │
│  │   ├── 00000000000000001000.log    (offset 1000-1999)   │
│  │   └── 00000000000000002000.log    (offset 2000+)       │
│  ├── Partition 1                                           │
│  │   ├── 00000000000000000000.log    (offset 0-999)        │
│  │   └── ...                                               │
│  └── Partition N                                           │
│                                                             │
│  每个Log Segment包含：                                       │
│  ├── .log：消息数据                                         │
│  ├── .index：偏移量索引（稀疏索引）                          │
│  └── .timeindex：时间索引（稀疏索引）                        │
└─────────────────────────────────────────────────────────────┘
```

## 2. 副本机制

### 2.1 副本分配

```
Kafka 副本机制：

┌─────────────────────────────────────────────────────────────┐
│  ISR (In-Sync Replicas)：同步副本集                         │
│  ├── Leader：处理读写请求                                   │
│  ├── Follower：复制Leader数据                               │
│  └── ISR = Follower中追上Leader的副本                       │
│                                                             │
│  选举机制：                                                 │
│  ├── ZK监听模式：Broker宕机，ZK触发选举                     │
│  └── KRaft模式：Raft协议自动选举                             │
│                                                             │
│  高水位 (HW)：                                             │
│  └── 所有ISR副本中最小的offset，只有≤HW的消息才committed      │
└─────────────────────────────────────────────────────────────┘
```

## 3. 生产者

### 3.1 发送流程

```
Kafka 生产者发送流程：

┌─────────────────────────────────────────────────────────────┐
│  1. 序列化：ProducerRecord → byte[]                         │
│  2. 分区：partitioner.keyPartitioner()                       │
│  3. 压缩：gzip/lz4/snappy                                   │
│  4. 缓冲区：RecordAccumulator（Batch）                       │
│  5. 发送：Sender线程异步发送                                 │
│  6. 确认：acks参数控制                                       │
│                                                             │
│  acks配置：                                                  │
│  ├── 0：不等待确认（最快，可能丢数据）                        │
│  ├── 1：等Leader确认（默认）                                 │
│  └── -1/all：等所有ISR确认（最安全）                         │
└─────────────────────────────────────────────────────────────┘
```

## 4. 消费者

### 4.1 消费模式

```
Kafka 消费者模式：

┌─────────────────────────────────────────────────────────────┐
│  1. Pull模式                                                 │
│  └── 消费者主动拉取，避免消息积压                             │
│                                                             │
│  2. 消费者组 (Consumer Group)                                │
│  └── 同一组内消费者不重复消费同一分区                          │
│                                                             │
│  3. Offset管理                                               │
│  └── 自动提交 vs 手动提交                                   │
│                                                             │
│  4. 位移重置策略                                             │
│  ├── latest：从最新开始                                      │
│  └── earliest：从最早开始                                    │
└─────────────────────────────────────────────────────────────┘
```
