# 消息队列可靠性深度解析

> 深入消息队列可靠性：消息不丢、不重放、顺序性保证。
> 源码级分析，包含生产环境最佳实践。
> 适用对象：后端工程师、架构师

---

## 1. 消息不丢保障

### 1.1 全流程可靠

```
消息不丢保障：

┌─────────────────────────────────────────────────────────────┐
│  生产者侧：                                                  │
│  ├── Confirm确认机制：Broker确认收到消息                      │
│  ├── 事务消息：原子发送                                       │
│  └── 本地消息表：异步补偿                                     │
│                                                             │
│  Broker侧：                                                  │
│  ├── 持久化存储：落盘保证                                     │
│  ├── 副本机制（ISR）：多副本同步                              │
│  └── 主从同步：确保数据不丢失                                 │
│                                                             │
│  消费者侧：                                                  │
│  ├── 手动ACK：业务处理完再确认                                │
│  ├── 消费重试：失败自动重试                                   │
│  └── 死信队列：长期失败的消息转入DLQ                          │
│                                                             │
│  最终一致性：                                                │
│  ├── 消息幂等性设计                                          │
│  ├── 业务补偿                                                │
│  └── 对账机制                                                │
└─────────────────────────────────────────────────────────────┘
```

## 2. 消息顺序性

### 2.1 保证策略

```
消息顺序性保证：

┌─────────────────────────────────────────────────────────────┐
│  分区有序：                                                  │
│  ├── 同一分区内消息有序                                       │
│  ├── 按消息Key路由到同一分区                                  │
│  └── Kafka：partition key决定分区                             │
│                                                             │
│  全局有序：                                                  │
│  ├── 单分区处理                                               │
│  └── 吞吐量受限                                              │
│                                                             │
│  业务有序：                                                  │
│  ├── 保证同一业务消息顺序                                     │
│  ├── 不同业务可并行处理                                       │
│  └── 常用方案                                                │
│                                                             │
│  实现：                                                      │
│  ├── Kafka：producer发送时指定partition key                   │
│  ├── RocketMQ：MessageQueueSelector                        │
│  └── RabbitMQ：routing key绑定                               │
└─────────────────────────────────────────────────────────────┘
```
