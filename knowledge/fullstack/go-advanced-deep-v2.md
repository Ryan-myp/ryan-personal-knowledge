## 1. Goroutine调度模型

### 1.1 GMP模型

```
Go调度器GMP模型：

┌─────────────────────────────────────────────────────────────┐
│  G (Goroutine) - 协程                                      │
│  ├── 代表一个协程的执行状态                                 │
│  ├── 包含：栈、PC指针、待执行函数                            │
│  └── 栈大小：2KB起始，动态扩容                               │
│                                                             │
│  M (Machine) - 机器线程                                     │
│  ├── 代表一个OS线程                                          │
│  ├── 绑定G执行                                               │
│  └── 数量：GOMAXPROCS（默认CPU核数）                         │
│                                                             │
│  P (Processor) - 处理器                                      │
│  ├── 代表一个逻辑处理器                                       │
│  ├── 维护本地任务队列                                        │
│  └── 数量：GOMAXPROCS                                        │
│                                                             │
│  调度关系：                                                  │
│  ┌───┐  ┌───┐  ┌───┐                                    │
│  │ P1│──│ P2│──│ P3│...                                   │
│  └─┬─┘  └─┬─┘  └─┬─┘                                    │
│    │      │      │                                       │
│    │  ┌───┴───┐                                      │
│    │  │ G Queue│                                      │
│    │  └───┬───┘                                      │
│    │      │                                            │
│    └──────┴───────────────────────────┐                │
│                                       ↓                │
│  ┌──────────────────────────────────────┐              │
│  │            G Cache (全局队列)          │              │
│  └──────────────────────────────────────┘              │
│                                       │                 │
│    ┌──────────────────────────────────┘                 │
│    ↓                                                    │
│  ┌──────────────────────────────────────┐              │
│  │           Work Stealing               │              │
│  │  (P忙时从其他P或全局队列偷取任务)         │              │
│  └──────────────────────────────────────┘              │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 调度器初始化

```
调度器初始化流程：

1. runtime.main() 启动
2. mstart() 初始化主线程
3. newproc() 创建第一个P（逻辑处理器）
4. gomaxprocs() 设置P的数量
5. schedule() 开始调度循环

关键参数：
  ├── GOMAXPROCS：逻辑处理器数量（默认=CPU核数）
  ├── GOGC：GC触发阈值（默认100%）
  └── GODEBUG：调试选项
```

### 2.2 上下文传递

```
Context 使用规范：

┌─────────────────────────────────────────────────────────────┐
│  1. Context 作为函数第一个参数                                 │
│  func DoWork(ctx context.Context, ...) error {              │
│      // ...                                                 │
│  }                                                          │
│                                                             │
│  2. 不要在结构体中存储 Context                                │
│     ❌ type Foo struct { ctx context.Context }              │
│     ✅ 作为参数传递                                          │
│                                                             │
│  3. 不要将 Context 传给长生命周期任务                          │
│     ✅ 短生命周期任务（请求级别）                             │
│     ❌ 后台任务、定时器                                       │
│                                                             │
│  4. Context 的派生                                            │
│     ├── context.Background()：根Context                     │
│     ├── context.TODO()：不确定时使用                          │
│     ├── ctx.WithCancel()：可取消                              │
│     ├── ctx.WithTimeout()：超时控制                           │
│     └── ctx.WithValue()：键值传递                            │
│                                                             │
│  5. Value 使用的注意事项                                      │
│     ├── 只用于请求级数据（如用户信息、traceID）              │
│     ├── 不要传递敏感信息                                     │
│     └── 键类型建议用自定义类型防止冲突                         │
└─────────────────────────────────────────────────────────────┘
```

## 3. 垃圾回收优化

### 3.1 GC 类型

```
Go GC 类型：

┌─────────────────────────────────────────────────────────────┐
│  1. Concurrent Mark (并发标记)                               │
│     ├── 与用户 goroutine 并发执行                             │
│     ├── 标记存活对象                                         │
│     └── 使用三色标记法                                        │
│                                                             │
│  2. Concurrent Sweep (并发清除)                               │
│     ├── 清除未被标记的对象                                    │
│     └── 释放内存                                            │
│                                                             │
│  3. STW (Stop The World)                                    │
│     ├── 初始化标记                                            │
│     ├── 扫描根对象                                           │
│     └── 强制同步（时间很短，<1ms）                            │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 GC 调优

```
GC 调优参数：

┌─────────────────────────────────────────────────────────────┐
│  环境变量：                                                 │
│  ├── GOGC=100（默认值，GC触发阈值）                         │
│  ├── GOGC=off（禁用自动GC）                                 │
│  ├── GOGC=50（更激进GC）                                    │
│  └── GOMEMLIMIT=1GiB（内存限制）                           │
│                                                             │
│  运行时控制：                                               │
│  ├── runtime/debug.SetGCPercent()                           │
│  ├── runtime/debug.FreeOSMemory()                           │
│  └── runtime.GC()                                          │
│                                                             │
│  性能优化建议：                                              │
│  1. 减少对象分配：复用对象（sync.Pool）                      │
│  2. 使用对象池：避免频繁分配小对象                            │
│  3. 减少指针：使用 []byte 替代 string                        │
│  4. 预分配容量：make([]T, 0, cap)                           │
│  5. 避免大对象：>32KB 直接进入大对象堆                        │
│  6. 使用内存复用：sync.Pool 用于临时对象                      │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 常见优化技巧

```
性能优化 Checklist：

┌─────────────────────────────────────────────────────────────┐
│  CPU优化：                                                   │
│  ├── 减少锁竞争：无锁数据结构、分片锁                        │
│  ├── 缓存友好：结构体字段顺序、局部性原理                    │
│  ├── SIMD优化：使用 unsafe 手动向量化                        │
│  └── 并行化：goroutine + channels                          │
│                                                             │
│  内存优化：                                                  │
│  ├── 复用对象：sync.Pool                                  │
│  ├── 避免逃逸：使用 make([]T, 0, n)                        │
│  ├── 减少分配：对象池、预分配                                │
│  └── 紧凑存储：使用 []byte 替代 string                      │
│                                                             │
│  并发优化：                                                  │
│  ├── 限制并发度：semaphore 模式                              │
│  ├── 避免锁竞争：无锁队列、分片map                           │
│  └── 批量处理：减少锁持有时间                                │
│                                                             │
│  I/O优化：                                                   │
│  ├── 异步I/O：非阻塞网络、epoll                              │
│  ├── 批量操作：批量写入、批量查询                            │
│  └── 缓冲：bufio、buffer pool                              │
└─────────────────────────────────────────────────────────────┘
```

## 5. 实战案例

### 5.1 高性能Web服务

```
高性能Web服务架构：

┌─────────────────────────────────────────────────────────────┐
│  ┌─────────────────────────────────────────────────────┐  │
│  │                  请求层 (Nginx)                      │  │
│  │  负载均衡 | 限流 | 缓存 | 日志                       │  │
│  └──────────────────────────────┬──────────────────────┘  │
│                                 ↓                         │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                  服务层 (Go)                         │  │
│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐  │  │
│  │  │API Server│ │RPC Server│ │Worker   │ │Scheduler│  │  │
│  │  └─────────┘ └─────────┘ └─────────┘ └─────────┘  │  │
│  └──────────────────────────────┬──────────────────────┘  │
│                                 ↓                         │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                  数据层                              │  │
│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐  │  │
│  │  │  MySQL  │ │  Redis  │ │  Kafka  │ │   ES    │  │  │
│  │  └─────────┘ └─────────┘ └─────────┘ └─────────┘  │  │
│  └─────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘

关键优化点：
  1. 连接池：DB Pool + Redis Pool
  2. 缓存策略：多级缓存（L1内存 + L2 Redis）
  3. 异步处理：消息队列解耦
  4. 限流保护：令牌桶 + 滑动窗口
  5. 监控告警：Prometheus + Grafana
```
