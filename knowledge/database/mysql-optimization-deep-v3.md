## 1. 索引优化

### 1.1 索引类型

```
MySQL 索引类型：

┌─────────────────────────────────────────────────────────────┐
│  1. 主键索引 (PRIMARY KEY)                                   │
│     ├── 唯一标识，不允许NULL                                 │
│     └── 每个表只能有一个                                       │
│                                                             │
│  2. 唯一索引 (UNIQUE)                                        │
│     ├── 允许NULL（但只有一个NULL）                            │
│     └── 值必须唯一                                           │
│                                                             │
│  3. 普通索引 (INDEX)                                        │
│     ├── 无限制                                               │
│     └── 可建在任意列                                         │
│                                                             │
│  4. 全文索引 (FULLTEXT)                                     │
│     ├── 适用于文本搜索                                       │
│     └── MyISAM/InnoDB（5.6+）                                │
│                                                             │
│  5. 联合索引 (COMPOSITE)                                     │
│     ├── 多列组成的索引                                        │
│     └── 遵循最左前缀原则                                      │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 最左前缀原则

```
最左前缀原则示例：

索引：(a, b, c)

✅ 可用索引：
  - WHERE a = 1
  - WHERE a = 1 AND b = 2
  - WHERE a = 1 AND b = 2 AND c = 3
  - WHERE a = 1 AND c = 3  （c会被过滤，但a可用索引）

❌ 不可用索引：
  - WHERE b = 2
  - WHERE c = 3
  - WHERE b = 2 AND c = 3

⚠️ 范围查询后中断：
  - WHERE a = 1 AND b > 2 AND c = 3  （c不可用索引）
```

## 2. 查询优化

### 2.1 EXPLAIN 分析

```
EXPLAIN 关键字段：

┌─────────────────────────────────────────────────────────────┐
│  type: 连接类型                                              │
│  ├── system：表只有一行                                     │
│  ├── const：常量查询，最多一行                                │
│  ├── eq_ref：唯一索引查询                                    │
│  ├── ref：非唯一索引查询                                    │
│  ├── range：索引范围查询                                     │
│  ├── index：全索引扫描                                       │
│  └── ALL：全表扫描（最坏情况）                                │
│                                                             │
│  possible_keys：可能使用的索引                                │
│  key：实际使用的索引                                         │
│  key_len：使用索引的长度                                      │
│  rows：估算扫描行数                                          │
│  Extra：额外信息                                             │
│  ├── Using filesort：需要额外排序                            │
│  ├── Using temporary：使用临时表                             │
│  └── Using index：覆盖索引                                   │
└─────────────────────────────────────────────────────────────┘
```

## 3. 锁优化

### 3.1 锁类型

```
MySQL 锁机制：

┌─────────────────────────────────────────────────────────────┐
│  InnoDB 锁类型：                                             │
│  ├── 全局锁：FLUSH TABLES WITH READ LOCK                    │
│  ├── 表级锁：LOCK TABLES                                     │
│  ├── 行级锁：                                               │
│  │   ├── 记录锁 (Record Lock)                               │
│  │   ├── 间隙锁 (Gap Lock)                                  │
│  │   └── 临键锁 (Next-Key Lock) = 记录锁 + 间隙锁            │
│  └── 元数据锁 (MDL)                                        │
│                                                             │
│  锁模式：                                                    │
│  ├── 共享锁 (S锁)：允许其他事务读                             │
│  └── 排他锁 (X锁)：独占，其他事务不能读写                      │
└─────────────────────────────────────────────────────────────┘
```

## 4. 配置调优

### 4.1 关键参数

```
InnoDB 关键配置参数：

┌─────────────────────────────────────────────────────────────┐
│  innodb_buffer_pool_size                                     │
│  ├── 最重要参数，占物理内存70-80%                            │
│  └── 缓冲池越大，磁盘I/O越少                                │
│                                                             │
│  innodb_log_file_size                                       │
│  ├── redo log文件大小                                       │
│  └── 越大，写入性能越好，但恢复时间越长                      │
│                                                             │
│  innodb_flush_log_at_trx_commit                             │
│  ├── 1：每次事务提交刷盘（最安全）                           │
│  ├── 0：每秒刷盘（性能最好）                                 │
│  └── 2：每次提交写OS缓存，每秒刷盘                          │
│                                                             │
│  innodb_io_capacity                                         │
│  ├── SSD：2000-5000                                        │
│  └── HDD：100-200                                          │
│                                                             │
│  innodb_flush_method                                        │
│  └── O_DIRECT：绕过OS缓存，直接IO                           │
└─────────────────────────────────────────────────────────────┘
```

## 5. 自测题

### 5.1 单选题

1. 联合索引(a,b,c)，以下哪个查询不能用索引：
   A. WHERE a=1  B. WHERE b=2  C. WHERE a=1 AND b=2  D. WHERE a=1 AND c=3
   答案：B

2. innodb_flush_log_at_trx_commit=1 表示：
   A. 每秒刷盘  B. 每次提交刷盘  C. 不刷盘  D. 随机刷盘
   答案：B
