## 1. Cluster架构

### 1.1 核心原理

```
Redis Cluster架构：

┌─────────────────────────────────────────────────────────────┐
│  哈希槽（Hash Slot）：                                       │
│  ├── 共16384个槽（0-16383）                                  │
│  ├── 数据按槽分布到不同节点                                    │
│  └── 节点负责部分槽的读写                                     │
│                                                             │
│  节点角色：                                                  │
│  ├── Master：主节点，负责读写                                 │
│  ├── Slave：从节点，负责故障转移                               │
│  └── 至少3个Master（保证高可用）                              │
│                                                             │
│  节点通信：                                                  │
│  ├── 节点间Gossip协议                                        │
│  ├── 定期交换元数据                                          │
│  └── 故障检测                                                │
│                                                             │
│  数据迁移：                                                  │
│  ├── 手动迁移：CLUSTER ADDSLOTS                              │
│  ├── 自动迁移：集群扩容时自动分配                              │
│  └── 迁移过程中服务不中断                                     │
└─────────────────────────────────────────────────────────────┘
```

## 2. 故障转移

### 2.1 主从切换

```
Redis Cluster故障转移：

┌─────────────────────────────────────────────────────────────┐
│  故障检测：                                                  │
│  ├── PFAIL：节点主观认为宕机                                  │
│  └── FAIL：多数Master认为宕机                                │
│                                                             │
│  故障转移流程：                                              │
│  1. Slave发现Master FAIL                                     │
│  2. Slave选举（Raft协议）                                    │
│  3. 胜出Slave提升为Master                                    │
│  4. 接管原Master的槽                                         │
│  5. 通知其他节点                                             │
│  6. 客户端重定向（MOVED/ASK）                                │
│                                                             │
│  客户端处理：                                                │
│  ├── 缓存槽位置映射                                          │
│  ├── MOVED：永久重定向                                       │
│  └── ASK：临时重定向                                         │
└─────────────────────────────────────────────────────────────┘
```
