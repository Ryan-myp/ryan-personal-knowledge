## 1. 索引设计

### 1.1 最佳实践

```
Elasticsearch索引设计原则：

┌─────────────────────────────────────────────────────────────┐
│  分片策略：                                                  │
│  ├── 单分片大小：30GB-50GB                                   │
│  ├── 总数据量 / 单分片大小 = 分片数                          │
│  └── 避免过多分片（查询开销大）                               │
│                                                             │
│  字段映射：                                                  │
│  ├── text：全文检索                                          │
│  ├── keyword：精确匹配、聚合                                  │
│  ├── date：日期类型                                          │
│  ├── float/long：数值类型                                    │
│  └── nested：对象数组                                        │
│                                                             │
│  索引模板：                                                  │
│  ├── 自动创建索引                                            │
│  ├── 统一映射配置                                            │
│  └── 轮转策略（如按日期）                                    │
│                                                             │
│  别名：                                                      │
│  ├── 索引别名透明切换                                        │
│  └── 零停机重建索引                                          │
└─────────────────────────────────────────────────────────────┘
```

## 2. 查询优化

### 2.1 性能调优

```
Elasticsearch查询优化：

┌─────────────────────────────────────────────────────────────┐
│  查询层面：                                                  │
│  ├── 避免match_all+大分页                                     │
│  ├── 使用search_after替代from/size                           │
│  ├── 减少聚合字段                                             │
│  └── 避免通配符前缀查询                                       │
│                                                             │
│  索引层面：                                                  │
│  ├── 合理设置分片数                                          │
│  ├── 关闭不必要的字段索引（index: false）                    │
│  ├── 使用doc_values优化聚合                                  │
│  └── 定期force_merge减少段数量                               │
│                                                             │
│  集群层面：                                                  │
│  ├── JVM堆内存：不超过31GB（压缩指针阈值）                   │
│  ├── 预热：节点重启后预热缓存                                │
│  └── 监控：索引速率、查询延迟、 heap使用                      │
└─────────────────────────────────────────────────────────────┘
```
