## 1. GMP调度模型

### 1.1 核心组件

```
Go调度器GMP模型：

┌─────────────────────────────────────────────────────────────┐
│  G（Goroutine）：                                           │
│  ├── 调度元数据                                              │
│  ├── stack指针（初始2KB，动态扩容）                          │
│  ├── pc（程序计数器）                                       │
│  └── 状态：running/runnable/generator/gcscan                 │
│                                                             │
│  M（Machine/OS Thread）：                                   │
│  ├── 执行Goroutine的OS线程                                   │
│  ├── P的引用                                                 │
│  └── 工作队列                                               │
│                                                             │
│  P（Processor）：                                           │
│  ├── 本地运行队列（最多256个G）                               │
│  ├── GOMAXPROCS个P（默认CPU核数）                           │
│  └── 全局队列窃取                                           │
│                                                             │
│  调度流程：                                                  │
│  1. G从本地队列执行                                          │
│  2. 本地队列空 → 从全局队列获取                               │
│  3. 全局队列空 → 从其他P窃取一半                             │
│  4. 阻塞/IO → 切换G，M被占或空闲                              │
└─────────────────────────────────────────────────────────────┘
```

## 2. 任务窃取

### 2.1 负载均衡

```
Go调度器任务窃取：

┌─────────────────────────────────────────────────────────────┐
│  工作窃取（Work Stealing）：                                 │
│  ├── P的本地队列满256个G时，一半放入全局队列                  │
│  ├── P本地队列为空时，从全局队列获取                          │
│  ├── 全局队列为空时，从其他P"偷"一半G                        │
│  └── 随机起点，避免竞争热点                                   │
│                                                             │
│  优势：                                                      │
│  ├── 负载均衡                                                │
│  ├── 减少锁竞争                                             │
│  └── 高效利用CPU                                             │
│                                                             │
│  边界情况：                                                  │
│  ├── 所有P都空闲：M进入休眠，等待新G唤醒                      │
│  ├── G阻塞：M被标记为空闲，调度器寻找新G                      │
│  └── 网络IO：G阻塞，M可以执行其他G                            │
└─────────────────────────────────────────────────────────────┘
```
