## 1. HikariCP调优

### 1.1 核心参数

```
HikariCP核心参数调优：

┌─────────────────────────────────────────────────────────────┐
│  连接池大小：                                                │
│  ├── maximum-pool-size：最大连接数                            │
│  │   计算公式：CPU核数 * 2 + 有效磁盘数                       │
│  │   或：QPS / (每秒单连接处理数)                            │
│  ├── minimum-idle：最小空闲连接                               │
│  └── idle-timeout：空闲超时（应 < max-lifetime）             │
│                                                             │
│  超时设置：                                                  │
│  ├── connection-timeout：获取连接超时（默认30s）              │
│  ├── leak-detection-threshold：泄漏检测阈值（默认0，建议60s） │
│  └── max-lifetime：连接最大生命周期（默认30min）              │
│                                                             │
│  其他参数：                                                  │
│  ├── connection-test-query：连接测试SQL                      │
│  ├── keepalive-time：保活时间（定期发送PING）                 │
│  └── initialization-fail-timeout：初始化失败超时              │
└─────────────────────────────────────────────────────────────┘
```

## 2. 连接泄漏检测

### 2.1 问题排查

```
连接泄漏检测与排查：

┌─────────────────────────────────────────────────────────────┐
│  泄漏检测：                                                  │
│  ├── 设置leak-detection-threshold=60000（60秒）              │
│  ├── 超时会打印堆栈信息                                       │
│  └── 监控日志中的Leaked connection记录                        │
│                                                             │
│  常见泄漏场景：                                              │
│  ├── try-with-resources未使用                                 │
│  ├── 异常分支未关闭Connection                                │
│  ├── 连接池配置不当导致连接耗尽                               │
│  └── 长事务持有连接                                           │
│                                                             │
│  排查步骤：                                                  │
│  1. 检查leak detection日志                                    │
│  2. 查看堆栈定位泄漏位置                                      │
│  3. 修复代码或调整配置                                        │
│  └── 监控连接池指标（active/idle/waiting）                   │
└─────────────────────────────────────────────────────────────┘
```
