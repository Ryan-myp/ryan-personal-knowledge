## 1. 两阶段提交（2PC）

### 1.1 协议流程

```
2PC协议流程：

┌─────────────────────────────────────────────────────────────┐
│  阶段一：准备阶段（Prepare）                                 │
│  ├── Coordinator发送Prepare消息给所有Participant            │
│  ├── Participant执行事务，但不提交                            │
│  ├── Participant投票（Yes/No）                               │
│  └── Coordinator等待所有响应                                  │
│                                                             │
│  阶段二：提交阶段（Commit）                                  │
│  ├── 所有Participant投票Yes → 发送Commit消息                │
│  ├── 任一Participant投票No → 发送Rollback消息               │
│  └── Participant执行提交/回滚                                │
│                                                             │
│  问题：                                                      │
│  ├── 阻塞问题：Coordinator宕机，Participant无法决定          │
│  ├── 单点故障：Coordinator成为瓶颈                           │
│  └── 同步阻塞：所有Participant等待                           │
└─────────────────────────────────────────────────────────────┘
```

## 2. TCC事务

### 2.1 Try-Confirm-Cancel

```
TCC事务模式：

┌─────────────────────────────────────────────────────────────┐
│  Try：                                                       │
│  ├── 执行检查（一致性）                                       │
│  ├── 预留资源（隔离性）                                       │
│  └── 不执行实际业务                                          │
│                                                             │
│  Confirm：                                                   │
│  ├── 使用Try预留的资源                                       │
│  ├── 执行业务逻辑                                            │
│  └── 不做强一致性检查                                        │
│                                                             │
│  Cancel：                                                    │
│  ├── 释放Try预留的资源                                       │
│  ├── 回滚业务操作                                            │
│  └── 不做强一致性检查                                        │
│                                                             │
│  特点：                                                      │
│  ├── 应用层实现                                               │
│  ├── 无锁，高性能                                             │
│  ├── 需要业务方实现三个操作                                    │
│  └── 适合金融场景                                            │
└─────────────────────────────────────────────────────────────┘
```
