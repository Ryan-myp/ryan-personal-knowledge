## 1. Paxos算法

### 1.1 核心概念

```
Paxos算法核心：

┌─────────────────────────────────────────────────────────────┐
│  角色：                                                      │
│  ├── Proposer：提出提案                                     │
│  ├── Acceptor：接受/拒绝提案                                 │
│  └── Learner：学习提案结果                                  │
│                                                             │
│  阶段：                                                      │
│  ├── Phase 1a：Proposer发送Prepare请求，携带提案编号          │
│  ├── Phase 1b：Acceptor回复Accept，如果编号更高               │
│  ├── Phase 2a：Proposer发送Accept请求，携带值                │
│  └── Phase 2b：Acceptor回复Accepted                         │
│                                                             │
│  结论：                                                      │
│  ├── 一旦提案被接受，就不会被覆盖                             │
│  ├── 多数派同意即可通过                                      │
│  └── 支持动态成员变化                                       │
└─────────────────────────────────────────────────────────────┘
```

## 2. Raft算法

### 2.1 领导选举

```
Raft领导选举：

┌─────────────────────────────────────────────────────────────┐
│  角色：                                                      │
│  ├── Leader：处理所有请求                                   │
│  ├── Follower：响应请求，复制日志                            │
│  └── Candidate：竞选领导者                                   │
│                                                             │
│  选举流程：                                                  │
│  1. Follower超时未收到心跳 → 转为Candidate                   │
│  2. Candidate发送RequestVote请求                             │
│  3. Follower投票给第一个请求的Candidate                      │
│  4. Candidate获得多数票 → 成为Leader                         │
│  5. Leader发送心跳保持权威                                   │
│                                                             │
│  日志复制：                                                  │
│  1. Client发送请求给Leader                                   │
│  2. Leader追加日志到本地                                      │
│  3. Leader发送给Follower复制                                 │
│  4. Follower确认后，Leader提交                               │
└─────────────────────────────────────────────────────────────┘
```
