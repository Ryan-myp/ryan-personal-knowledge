## 1. 雪花算法

### 1.1 核心设计

```
雪花算法（Snowflake）设计：

┌─────────────────────────────────────────────────────────────┐
│  64位ID结构：                                                │
│  ┌──────┬─────────┬──────────────┬────────┬──────────┐    │
│  │ 符号  │ 时间戳   │ 机器ID       │ 序列号  │          │    │
│  │ 1bit │ 41bits  │  10bits      │ 12bits │          │    │
│  └──────┴─────────┴──────────────┴────────┴──────────┘    │
│                                                             │
│  时间戳（41位）：                                            │
│  ├── 当前时间戳（毫秒）                                      │
│  ├── 可用69年（2^41 - 1 ms）                                │
│  └── 基于固定起始时间计算                                    │
│                                                             │
│  机器ID（10位）：                                            │
│  ├── 最多1024个节点                                         │
│  ├── 可分区部署                                             │
│  └── 需提前分配                                             │
│                                                             │
│  序列号（12位）：                                            │
│  ├── 每毫秒最多4096个ID                                     │
│  ├── 同一毫秒内自增                                         │
│  └── 超过则等待下一毫秒                                     │
└─────────────────────────────────────────────────────────────┘
```

## 2. 号段模式

### 2.1 数据库方案

```
号段模式（Segment）实现：

┌─────────────────────────────────────────────────────────────┐
│  表结构：                                                    │
│  ┌──────────┬───────────┬───────────┬───────────┐          │
│  │ id       │ max_id    │ step      │ biz_type  │          │
│  ├──────────┼───────────┼───────────┼───────────┤          │
│  │ 1        │ 1000      │ 2000      │ order     │          │
│  └──────────┴───────────┴───────────┴───────────┘          │
│                                                             │
│  流程：                                                      │
│  1. 从max_id + 1开始使用                                    │
│  2. 用完step数量后更新max_id                                │
│  3. 原子更新（UPDATE ... WHERE max_id < ?）                  │
│                                                             │
│  优势：                                                      │
│  ├── 连续ID，数据库友好                                      │
│  ├── 批量获取，减少DB访问                                    │
│  └── 实现简单                                               │
│                                                             │
│  劣势：                                                      │
│  ├── 依赖数据库                                              │
│  └── DB故障影响ID生成                                        │
└─────────────────────────────────────────────────────────────┘
```
