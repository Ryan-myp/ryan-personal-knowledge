# 可观测性系统设计深度解析

> 深入可观测性：Metrics、Logs、Traces、SLO。
> 源码级分析，包含Prometheus/Grafana/ELK最佳实践。
> 适用对象：SRE、运维工程师

---

## 1. 可观测性三大支柱

### 1.1 Metrics

```
Metrics 指标类型：

┌─────────────────────────────────────────────────────────────┐
│  Counter：只增不减，如请求总数                                │
│  ├── 用途：统计事件发生次数                                  │
│  └── 示例：http_requests_total                              │
│                                                             │
│  Gauge：可增可减，如当前内存使用量                            │
│  ├── 用途：表示当前状态值                                    │
│  └── 示例：process_resident_memory_bytes                    │
│                                                             │
│  Histogram：统计分布，如请求耗时                              │
│  ├── 用途：记录分布和分位数                                   │
│  └── 示例：http_request_duration_seconds_bucket             │
│                                                             │
│  Summary：客户端计算的分位数                                  │
│  └── 示例：http_request_duration_seconds_summary            │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Logs

```
日志系统设计：

┌─────────────────────────────────────────────────────────────┐
│  日志采集：                                                  │
│  ├── Filebeat/Fluentbit：日志采集代理                        │
│  └── Kafka：日志缓冲队列                                    │
│                                                             │
│  日志存储：                                                  │
│  ├── Elasticsearch：分布式搜索存储                           │
│  └── Loki：轻量级日志系统（标签索引）                        │
│                                                             │
│  日志分析：                                                  │
│  ├── Kibana/Grafana：可视化分析                              │
│  └── Promtail/Loki：日志查询                                 │
└─────────────────────────────────────────────────────────────┘
```

## 2. SLO/SLI/SLA

### 2.1 指标定义

```
SRE 指标体系：

┌─────────────────────────────────────────────────────────────┐
│  SLI (Service Level Indicator)：服务等级指标                 │
│  └── 实际测量的服务质量指标，如请求延迟、错误率               │
│                                                             │
│  SLO (Service Level Objective)：服务等级目标                 │
│  └── 对SLI的目标值，如99.9%的请求延迟<200ms                  │
│                                                             │
│  SLA (Service Level Agreement)：服务等级协议                 │
│  └── 与用户约定的SLO，不达标需赔偿                           │
│                                                             │
│  错误预算：                                                  │
│  └── 允许失败的额度 = 1 - SLO目标                            │
│      例：SLO=99.9%，错误预算=0.1%                            │
└─────────────────────────────────────────────────────────────┘
```
