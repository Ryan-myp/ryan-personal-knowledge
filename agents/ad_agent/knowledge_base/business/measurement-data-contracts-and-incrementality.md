# 广告测量数据契约、对账与增量评估

广告平台、网站/App 事件、MMP/CRM、订单和财务系统回答的是不同问题。平台报表适合优化平台交付，后端订单适合确认业务结果，实验或准实验才更接近增量效果。没有统一数据契约时，Agent 不应把多个系统的数字直接相加。

## 最小数据契约

每条报表或事件记录至少带上：平台、账户/资源层级、资源 ID、事件名、事件时间、账户时区、币种、金额口径、归因窗口、数据更新时间、来源系统、去重键和是否用于优化。金额要区分媒体花费、订单收入、毛利和预测 LTV；转化要区分发生、接收、归因、报告可见和入模五个状态。

## 对账顺序

1. 先核对日期范围、时区、币种、过滤、层级、字段/维度和归因设置。
2. 再核对展示、点击、花费、事件接收、平台归因、订单和退款的时间延迟。
3. 用资源 ID、事件 ID、订单 ID 或稳定组合键去重，检查重复、漏报和延迟回补。
4. 对账时保留原始快照，不用后一次拉取覆盖前一次结果；标记数据新鲜度。
5. 解释差异时先区分口径差异、归因差异、延迟差异和真正的数据链路故障。

## 归因与增量

| 口径 | 能回答 | 不能回答 |
|---|---|---|
| 平台归因 | 平台在自身窗口内分配了哪些转化 | 没有广告时是否也会发生 |
| 最后触点/规则归因 | 业务规则下的渠道贡献 | 渠道之间的因果增量 |
| Geo/时间实验 | 某种投放变化的增量证据 | 自动解释所有外部波动 |
| Holdout/随机实验 | 在设计条件下的因果差异 | 未控制的季节和供给变化 |
| Cohort/LTV | 不同投放批次的长期价值 | 单独证明媒体增量 |

实验报告要写清实验单位、分流方式、干预、观测窗口、主要指标、保护指标、样本量、置信区间或不确定性、外部干扰和停止规则。前后对比、相关性和平台归因不能被表述为确定的增量结论。

## 诊断边界

平台数字高而后端低：先查事件、去重、退款、延迟和归因窗口；后端高而平台低：查 Consent、浏览器/服务器链路、事件映射和归因限制；媒体交付异常而事件正常：查预算、竞价、库存、审核和定向。任何自动优化前都要把数据质量状态带入决策。

## 数据字典模板

每个指标都维护：名称、业务定义、数学公式、分子/分母、事件来源、主键、时区、币种、归因窗口、刷新周期、延迟分布、可加性、负责人和失效条件。指标重命名或公式变化时提升 schema 版本，不静默覆盖历史。

| 数据状态 | 允许消费方 | 必须携带的说明 |
|---|---|---|
| raw | 数据工程/排障 | 原始来源、抓取时间、脱敏状态 |
| complete | 报表分析 | 分页/任务完整、查询契约 |
| mature | 预算与策略 | 归因窗口、事件延迟、样本量 |
| reconciled | 财务/业务复盘 | 订单/CRM 对账和退款口径 |
| causal | 增量决策 | 实验设计、不确定性和外部干扰 |
