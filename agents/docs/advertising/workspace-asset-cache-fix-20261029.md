# 工作区新旧脚本混用修复

用户打开历史对话时出现 `renderedAssistantTurnIds is not defined`。上一轮新增了共享状态，
但入口 HTML 和脚本加载器仍使用原来的手工版本字符串，浏览器可复用旧 `chat-state.js`，
同时加载新聊天模块。原有 Node 单测始终装载最新文件，没有覆盖浏览器混合版本。

本轮在 Chromium 中模拟仍持有旧状态脚本的缓存，完整页面打开历史时复现了相同错误。
修复后同一旧版本缓存入口不再被请求，历史加载、新建对话、刷新后再次加载均通过。
浏览器验证使用本地会话 fixture，拦截非 GET 和非本地请求，未访问模型或广告 Provider。

## 修复

- 部署层 `WorkspaceAssets` 在进程启动时对 JS/CSS 文件名与内容生成统一摘要，不在请求中扫描文件。
- HTML 的脚本和样式入口使用该摘要；加载器从自身 URL 继承版本，传递给所有预加载和模块。
- CSS 子文件也使用同一个版本。HTML 返回 `no-store`；静态文件返回 `no-cache`，保留 ETag/304 校验。
- 增加依赖文件变化、确定性摘要、页面版本、所有模块/预加载版本和 HTTP 缓存头回归。

不修改 Run、权限、Tool、Provider、数据库或用户记录。发布仍需重启进程以生成新版本，
浏览器刷新页面即可获取；无需用户自行清除浏览器缓存。回滚时一并回滚部署入口、静态服务、
模板与加载器并重启，避免只还原其中一部分。
