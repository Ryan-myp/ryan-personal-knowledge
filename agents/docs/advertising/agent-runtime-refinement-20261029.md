# Agent 上下文、复盘证据与工作区可靠性优化

本轮根据离线复现修复五处问题，沿用单 Agent、Run Kernel、Registry 和既有持久化接口。没有新增渠道路由分支，没有发起真实 Provider 或外部模型请求。

## 改动与契约

| 问题 | 改动 | 边界 |
| --- | --- | --- |
| 候选 Tool 含多个 namespace 就绕过初始预算 | 仅显式多渠道请求或可信多账户上下文保留完整候选；其他候选使用预算。优先保留排名第一的能力和已声明的蓝图入口，并给不同 namespace 首次选择机会 | 不裁剪 Tool schema；明确选定的蓝图仍保留完整流程；未初始加载的 Tool 可通过既有 discovery 加载 |
| 某个大 schema 放不下就停止选择 | 跳过该候选，继续检查能放入预算的后续能力 | 不因此放宽权限、账户范围或 live gate；首选能力和蓝图入口仍是软预算例外 |
| 长约束从中间被截断，最新修改不可见 | 语义约束按最新优先展示，旧式约束共用 1600 字符预算；只保留完整记录，附遗漏数量和读取完整约束的 Tool 名称 | 不改变存储的完整约束、来源校验、版本和 advisory 性质 |
| 批量调用因同名而无法关联复盘 | 先校验 Tool 的渠道与资源契约，再按实际账户和资源筛选审计记录；同目标多次调用继续明确报歧义 | 回读必须有 `data_status=live`；模拟、失败和未知来源均不可确认优化结果；超过 100 条审计记录明确拒绝，避免截断后误认唯一 |
| 脚本 HTTP 200 但执行失败，页面仍假装加载成功 | 捕获当前模块的执行错误，停止后续初始化，显示刷新入口；网络错误仍在原模块重试 | 不在页面显示原始异常；部分执行后的脚本不能原地重复执行；加载完成或失败都清理监听器 |
| CSS HEAD 长度与 GET 不一致 | HEAD 返回与 GET 一致的 Content-Length 和缓存头，不返回正文 | 不改变资源版本生成和缓存验证策略 |

Tool 输入 schema、API 路由、数据库 schema 和 Provider contract 均不变。复盘证据要求更严格：旧审计如果没有可信的 live 标记，需要新的合法回读；不能补写或伪造该标记。同一目标同轮多次调用和列表数组路径的细粒度关联仍需后续扩展，当前不会猜测某一条成功记录作为结论。

## 离线 Prompt 采样

采用同一 `benchmark_prompt_payload.py`，捕获真实组装的消息和 Tool schema，模型返回固定文本，禁止 socket 连接。单位是序列化字符，不是 token，也不是响应延迟。

| 场景 | 优化前字符 | 优化后字符 | 前/后 Tool 数 |
| --- | ---: | ---: | ---: |
| 问候 | 24472 | 24472 | 2 / 2 |
| 能力介绍 | 31956 | 31956 | 2 / 2 |
| 程序化广告知识 | 65540 | 50222 | 33 / 6 |
| 报表 | 33087 | 33087 | 2 / 2 |
| 模板 | 46378 | 46378 | 10 / 10 |
| 创建 | 41368 | 41368 | 10 / 10 |
| 继续上文 | 43365 | 49479 | 5 / 9 |

知识样本减少约 23.4%。继续上文样本因超大候选不再阻断后续可用 Tool 而增加，不能据此声称所有场景都减小了 Prompt。自然语言选择质量仍需真实模型的重复评测，本轮没有进行该评测。

## 验证与交付

- 先写测试并复现预算、最新约束缺失、证据歧义、未知来源回读、窗口截断及浏览器执行错误，再实现修复。
- 针对性测试覆盖明确多渠道、模糊账户不偏向单渠道、来源与身份隔离、失败记录、边界和网络重试。
- Chromium 使用隔离的会话 fixtures，模拟执行报错、验证刷新恢复、新建与打开历史；仅访问本机静态资源，不发送后台写请求。
- `make ad-agent-check` 通过：3424 项 Python 测试、232 项前端测试、328 个 Tool 契约、86 篇知识；知识审计零错误、零警告。
- 针对性 64 项 Python 测试通过，五个主要改动模块合计行覆盖率 94.16%。增量 QGuard 无新增发现，`git diff --check` 通过。结构化结果见同名 evidence JSON。
- 全仓 QGuard 仍有既有技术债：784 个文件、4997 条发现、评分 0；增量质量门禁单独核对，不能将其等同于全仓通过。
