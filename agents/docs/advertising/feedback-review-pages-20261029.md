# 反馈审核分页与筛选（2026-10-29）

## 行为

负反馈审核列表从固定读取前 100 条改为数据库分页。默认每页 10 条，可切换 20 / 50 条，并显示总条数和页码。支持全部 / 待审核 / 已收录 / 已忽略，关键词匹配用户问题、当时回答、反馈原因与期望行为，以及全部时间或最近 7 / 30 / 90 天。筛选只作用于审核列表，顶部趋势统计仍使用独立的统计范围。

筛选后返回第一页；审核操作成功后刷新当前页并补位，末页变空时回到有效末页。编辑过的期望行为和 JSON 断言保留在当前浏览器页面的内存草稿中，翻页、筛选、读取失败重试不会清空；整页刷新不保留未提交草稿。旧请求不能覆盖新筛选，关闭页面后晚到的请求不再更新内容。

## 契约与权限

`GET /feedback/review` 新增可选 `page`、`q`、`since`、`until`，状态增加 `all`。分页返回原有 `status`、`items` 以及 `pagination`（page、limit、total、pages、has_next、has_previous）。不传新参数的调用仍返回原列表结构，回归样例导出仍只取人工已收录记录、最多 100 条，不随当前页面筛选改变。

分页沿用 Runtime → conversation feedback service → SessionManager → store。查询每页只做 COUNT 和 SELECT，读取有长度限制的文本；不会扫描并反序列化完整对话再在前端切页。分页上限 100 条，页码上限 10000，关键词上限 200 字符。时间由 API 转 UTC，起始包含、结束排除。排序使用提交时间和 feedback ID，避免相同时间导致分页顺序不稳定。

保留 `feedback.review` 权限与租户级审核范围：同租户 reviewer 可以审核该租户反馈，传入的 tenant_id 不改变可信 principal；查询还核对反馈所属会话的租户。SQL 结构使用内部固定字段，用户值全部绑定参数；`%`、`_`、`!` 按字面搜索。结果继续通过现有凭证脱敏。未改变反馈写入、人工收录或广告执行门禁。

## 恢复和部署

没有数据库迁移。无效参数返回 422，无审核权限返回 403，存储不可用返回 503。页面保留筛选和内存草稿并允许刷新重试。没有新增广告渠道请求或模型调用，也没有在实际数据库中提交审核。

原 LaunchAgent、配置和数据库保持一致，重启前检查无活跃 Task 或 Session lease，继续在 `0.0.0.0:8766` 提供服务。静态资源版本 `20261029-feedback-pages-v1`。回滚时同时回滚新增分页 API、service/store 和前端资源并重启原服务；无需恢复或删除数据。沿用现有错误和运维机制，没有新增观察性基础设施。
