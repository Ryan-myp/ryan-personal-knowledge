# 对话执行说明的语言一致性

## 范围与行为

- Harness 从当前用户原始请求确定中英文输出提示，不再从最后一条工具或文档内容猜测语言。
  中文请求中的 API 字段、代码和专有名称保留原样；数字续答从最近用户消息继承语言。
  当前检测覆盖中英文，不声称支持任意语言检测。
- HTTP 部署层基于真实模型调用、工具开始及工具结果事件生成简短执行说明，
  工具步骤优先使用已注册 Tool 声明的当前语言 intent alias，说明选择它的用途；
  模型结束事件和 Tool 结果事件只呈现可核验的工具数量、结果数量和后续动作。
  不直接向页面转发模型内部推演，不新增翻译模型调用或广告 Provider 调用。
- 页面沿用单条消息、流式追加、完成后自动折叠；说明框移入最终回复后，
  展开、收起按钮继续保留原语言和正确的无障碍状态。

## 接口与数据

`POST /chat/stream` 保留兼容事件名 `reasoning_delta`，新增明确类型标记：

```json
{
  "type": "reasoning_delta",
  "event_type": "reasoning_delta",
  "content_type": "execution_summary",
  "language_code": "zh",
  "status": "running",
  "content": "正在检查请求所需的信息与当前可用工具。\n"
}
```

页面只渲染带 `execution_summary` 标记的说明。原生 `model_reasoning_delta`、
`model_delta` 和未标记的旧 `reasoning_delta` 不作为可见进度。
会话详情、最近 Run、Run 事件回放接口同样过滤原始模型片段；
过滤不改写存储，不改变 `latest_seq` 游标，以免空页反复轮询同一批事件。
既有历史原文不会被自动翻译为新的执行说明。

语言继承读取使用可信 principal 的用户、租户范围，最多读取最近两条消息；
明确中英文请求不额外读取历史。执行说明不回显工具参数、凭证或模型原文。
权限、测试账户、live 门禁、确认、幂等和 Run 生命周期保持不变。

## 验证与回滚

验证包括中英文混排、数字续答、工具文本不影响语言、确认和错误结果、
历史回放游标与身份范围，以及说明框合并后仍可折叠。
API 使用 Runtime 替身，浏览器使用截获的 SSE 响应；没有调用广告渠道 API，
不代表重新验证了平台查询或创建能力。

新增语言和执行说明模块的聚焦行覆盖率为 98%。增量质量门禁通过；
全仓 qguard 仍未达标，不能把增量结果当作全仓质量通过。
无数据库迁移。回滚时应同步部署前后端静态版本，保留原数据库及配置；
不应为了恢复旧界面而重新开放内部推演原文。
