# 广告 Agent 第二轮通用能力优化

日期：2026-10-28。承接 [上一轮评估](system-upgrade-20261028.md)。
本轮围绕长任务上下文、列表后的连续追问、工具元数据处理性能和失败诊断进行修复。
使用本地模型替身和离线契约测试，没有调用广告 Provider 或真实模型，也不更新渠道 live 验收账本。

## 发现与落地

| 发现的问题 | 所属边界与改动 | 验收方式 |
| --- | --- | --- |
| 同一用户任务连续读取大列表后，当前回合字符数超限，无法进入下一次模型调用 | Harness `evidence_compaction.py` 生成有界只读结果预览，接入 transcript 字符上限和完整模型输入上限 | 三次查询累计超限仍可完成；调用次数不增加；原始记录不修改；系统指令、用户目标、调用 ID、参数保持不变 |
| Catalog 列表选择只支持对象形式的 Tool；dict Tool 的名称、schema 和 target 筛选不一致 | 通用 `conversation_selection` 和 Harness target 筛选统一读取已注册 metadata | 对象/dict 两种定义均支持按名称或完整 ID 追问；当前 allowlist 继续生效 |
| 同 namespace 下，不同资源具有相同 ID/名称时会被错误去重，可能选错详情 | 去重身份加入 `resource_type`；多匹配保持不确定，不任意选一个 | record/invoice 同 ID 的独立回归；write effect 不能因 action=get 被当成只读 |
| 每次工具评分重复分词稳定元数据，并复制完整 schema | 按元数据内容缓存不可变词项，读取 schema.properties，兼容仅提供 to_dict 的旧 schema | 元数据更新立即生效、分数一致、不缓存用户查询、超长元数据不入缓存 |
| ContextProvider 清理异常被静默忽略 | 沿用既有事件接口增加 `context_cleanup_error`，记录 Run 标识与异常类型 | 清理失败不覆盖已完成结果，异常文本不进入事件 |

以上修改均属于现有单 Agent Harness。没有新增业务 Router、渠道分支、独立 Runtime 或外部服务。
Tool/Skill 注册、意图声明、权限及 Provider 执行入口继续使用既有契约。

## 长任务压缩的准确性边界

压缩只处理**已完成、明确声明为 read、success=true、声明了 result_items_key 的列表结果**。
调用必须与前面的 assistant tool_call 按 ID 和名称匹配；孤立结果不会被压缩。
先处理较早结果，较新的证据尽量完整保留。处理分两级：保留可容纳的完整行；如果单行过大，
保留明确声明的 result_id_fields 和 result_summary_fields。至少保留一行或一个完整身份，
不会把 ID 截成部分字符串，也不会凭空计算未返回的业务指标。

每个压缩结果包含 `context_compaction`，说明原可见行数、遗漏行数和是否省略字段；
同时更新 `query_summary.context_count/context_truncated`。原有返回数量、来源状态、查询口径、
分页标记和 cursor 保持原值。模型可见样本不等于全账户数据，不能据样本臆测完整统计。
重复压缩保持第一次原行数，避免将样本伪装成完整结果。

以下内容保持完整：系统指令、用户输入、工具调用参数、write 结果、失败原因、未知效果、
待确认或待输入内容。完整最低信息仍放不下，或消息数量超过上限时，继续返回明确的
`model_input_limit_exceeded`。这不是无限上下文，也不是对任意长文本的 LLM 摘要。

压缩仅产生模型视图，不写回原消息、不新增工具调用，也不改变依赖参数绑定、权限、确认、
重放或幂等记录。恢复时依旧从原始 checkpoint/transcript 取得执行事实，再生成模型视图。
`tool_evidence_compacted` 仅报告消息数量和字符数，避免将查询内容放进诊断事件。

## 性能证据

可复现命令：

```bash
./scripts/ad-agent-python scripts/advertising/benchmark_context_preparation.py
```

- 使用已保存的 321 个 Tool 契约，对同一合成问题各采样 20 次。
  关闭元数据缓存时评分 P50 为 16.783 ms，启用后为 9.888 ms，约降低 41.1%；所有评分一致。
  这是评分子过程，不包含完整选择、知识检索、网络或模型响应时间。
- 元数据缓存最多 2048 项，单项输入最多 2048 字符；返回不可变词项，超过限制的元数据正常
  计算但不缓存。缓存键为声明内容，因此变更不依赖手工失效；用户查询不存入该缓存。
- 8 组只读结果的合成样本，消息序列化字符数由 136831 降到 31302，预算为 32000，
  20 次压缩 P50 为 3.364 ms。所有消息身份保留，原始消息仍为 136831 字符。
- 证据：[context-performance](../../evals/advertising/evidence/system-round2-context-performance-20261028.json)。

## 验证与剩余风险

新增测试先复现失败，再实现修复；第一批 catalog/评分用例为 8 failed / 2 passed，
压缩模块在实现前导入失败，清理诊断用例也确认旧实现缺少事件。
修复后，工具发现、模板目录选择、模型输入边界与本轮用例共 155 项回归通过。
压缩与清理诊断 27 项定向回归通过，新增压缩模块行覆盖率为 96%。

- `make ad-agent-check` 退出码为 0，**3256 项测试通过，1 个警告，耗时 305.49 秒**；
  编译、能力审计、321 个 Tool 契约快照和知识检查通过。85 篇知识页面无错误或警告。
- 最后的小范围重构再次通过编译及 27 项压缩/清理回归。覆盖率使用 Python tracer 测量；
  本环境缺少 coverage C tracer，已自动回退，不影响上述 96% 行覆盖统计。
- 增量静态检查扫描 41 个变更 Python 源文件：HEAD 基线 503 条、当前 500 条、新增 0 条，
  增量门禁通过。该范围包括前几轮尚未提交的修改，不能将差值全部归因于本轮。
- 全仓 QGuard 扫描 760 个源文件、4990 条发现，门禁仍失败；未放宽规则或修改质量阈值。
- `git diff --check` 通过。验证汇总见
  [verification](../../evals/advertising/evidence/system-round2-verification-20261028.json)。

本轮没有测量自然语言开放场景准确率，也没有进行生产并发压测。
模型延迟、复杂意图泛化、非列表长文本压缩、知识专业审查及全仓历史质量债务仍需继续治理。
