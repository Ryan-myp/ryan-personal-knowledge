# 通用 Agent 基础能力复核与加固

基于 `f18a565` 复核。这一轮优先修实现缺口，没有增加新的 Runtime、
业务 Router、Provider API 或凭证入口，也没有修改会话、模板与知识库数据库。

## 发现与实现

| 缺口 | 实现归属 | 验证依据 |
| --- | --- | --- |
| Tool 入队后提交失败，仍可能留下执行任务 | Harness `tool_execution.py`：admission Future，提交成功才允许进入执行器 | 入队后抛错、回收槽位、后续调用恢复 |
| 非布尔控制字段可能被当成成功 | 同一执行边界严格验证结果协议，不转换 `"false"`、数字或 null | 正常布尔、畸形字段、只读失败、写入结果不确定 |
| 已进入写执行器的异常不能证明没有写入 | 写调用异常标为 `effect_state=unknown`、`recovery_required=true` | 意外异常与明确结构化拒绝分别测试 |
| 异常文字绕过 Tool 输出预算 | 先限长、再脱敏，技术性结果协议错误不可自动反复修复 | 超长异常与凭证形状文本 |
| 通用上下文会先耗尽整个结果迭代器 | `context.py`：有限消费，只保留实际交付片段的来源元数据 | 限量迭代、大元数据、空项、来源故障 |
| Skill 名称、描述和版本未遵循文件声明 | `skills/metadata.py`：有界解析已支持的声明格式，复用版本校验器 | 标准声明、嵌套声明、非法 YAML、符号链接 |
| 已注册 Skill 仍能被外部字典修改 | 深层只读快照，拒绝非数据、非有限值与递归膨胀 | 发布方字典变更、递归与结构上限 |
| 场景来源范围被当成全部激活 | `source_ids` 仅限定候选池；相关性和 `always_on` 决定是否注入 | 非广告场景与来源隔离 |
| 每轮扫描长正文，分词与引用索引还不一致 | 注册时编译索引；统一 Unicode/连字符分词；有限 LRU | 精确引用、跨业务导出、重复命中与发布失效 |
| 指引文本可能把误放的凭证带入模型或缓存 | 通用 Context 消息入口与 Skill 缓存前统一脱敏；校验错误不回显原始 Header | Provider 文本、引用内容、等价字段名、私有校验值 |
| 能力目录忽略身份权限，截断还会丢掉执行边界 | 应用目录复用平台权限解析，按 principal 和账户范围收敛，优先保留模式边界 | 只读身份、live 权限、租户来源、目录截断 |
| 评测遗漏交互调用、转换布尔值、可能误过错误文字 | 平台 `execution_evidence.py` 提供执行账本与状态校验 | 交互调用、合并/延后、异常 Run、畸形证据 |
| 否定查询和相邻子句影响了流程说明 | 复用通用动作/别名解析，限定否定作用域，不把被禁止的读取当成指令 | 中英文否定、正向混合请求、注册别名 |

没有在中心选择器中新增渠道、公司名或特定问句分支。
动作与否定处理仍是有限启发式，不代表已经证明普遍语义理解准确。

## 契约与边界

### Tool 执行

只有执行器确实进入后抛出的异常，才走“可能已产生写效果”的保守处理。
提交失败、容量不足与明确返回的结构化拒绝，不会被直接描述成已完成写入。
效果未知不是回滚完成，也不是生产环境的自动核实凭证；仍需原有幂等、审计和恢复链路。

保留可重试读取的原始异常类型判断。没有让不安全写入获得额外重试权限。
所有真实渠道操作仍经过既有权限、白名单、模式和确认门禁。

### Skill

- 身份、描述和版本以 `SKILL.md` 的声明为准，不再用目录名覆盖声明。
- `source_ids` 是来源范围，不代表把范围内所有 Skill 无条件注入。
- 常驻指引通过受信任 binding 的 `metadata.always_on=true` 声明。
- 根指引上限为 100000 字符；references 最多 128 个文本文件、单文件最多
  100000 字符、合计最多 400000 字符，并限制目录项数量。
- 不读取或执行包里的 `scripts/`；references 符号链接会被拒绝。
- 元数据只允许有界的有限数据值；注册快照不能通过外部字典改变。
- 上下文缓存默认最多 64 项，容量必须为正整数；键由请求摘要、来源范围和
  发布代次组成，不保存查询明文。发布/卸载会失效缓存，旧并发构建不能回填新代次。

这些是接口行为修正，不保留目录名别名或另一套激活逻辑。没有数据库迁移。

### 评测

新增 `tool_executions`，从 Harness 原始 `tool_results` 生成，而不是从 UI 隐藏或
过滤后的业务结果反推。状态区分 `completed`、`failed`、`deferred`、`coalesced`；
记录调用身份与状态，不复制参数、结果正文或交互 payload。

存在账本时，Tool 断言以它为准；交互调用也计入调用数，延后和合并行不能证明成功。
`completed` 只表示该 Tool 的成功结果，不等于真实 Provider 写入已经验证。
通用流程图用例另外加严：必须返回 Mermaid、不需要补问、不调用 Tool；
此前“追问渠道但提到了流程”的回复不能再被当作完成画图。

保留实际 Run 状态。没有显式声明期望失败时，失败、取消、待核实和部分失败 Run
不能只凭“错误说明非空”就通过。需要验收拒绝路径时，使用声明式 `run_status` 断言。
没有放宽已有对话用例来换取通过率。
新增脱敏路径同时保留明确的非负整数 token 预算与用量指标，
不会把 `max_output_tokens` 等执行配置当成凭证抹掉；
真正的 access token 和错误类型的同名值仍受保护。

Skill-up 启动配置改为项目解释器，默认评测超时统一为 500 秒。本机缺少外层
`skill-up` CLI，因此外层命令没有跑通；直接 Runtime adapter 的测试与真实模型回归
单独记录，不能冒充完整 Skill-up CLI 验收。

## 性能口径

本地合成场景：32 个 Skill、100 次重复构建，首次约 6.174ms，
缓存 P50 约 0.003ms、P95 约 0.004ms。没有 Provider 调用。
这是 Skill 上下文构建测量，不是端到端聊天、生产吞吐或模型服务 SLO。

仍没有解决整个模型请求的统一硬预算。原有目录、业务上下文、历史和 Skill
各自受限，不等于整个请求很小。模型回归还可能受到上游错误、重试和较大输入影响。

## 交付与剩余项

最终 `make ad-agent-check` 通过 2706 项测试，321 份 Tool 契约快照、
Provider 契约审计、知识审计和向量缓存检查均通过。五个重点模块的聚焦
语句覆盖率为 95%，不是整个仓库或整个 Run Kernel 的覆盖率。

真实模型使用当前 `agnes-3.0-flash`，广告 Provider 全离线，网页搜索使用显式 fixture。
最后一批原规则样本为基础 8/8、改写 4/4；但人工复核发现流程图问题。
将同一批记录按加严规则重放后是 7/8，不能把此前 8/8 当作全部完成。
修复后独立实调的中英文严格流程图用例为 2/2：有 Mermaid、无补问、零 Tool 调用。
这些都不是未见泛化测试，不能合并成普遍正确率。

模型接口曾返回 `520`，重试后恢复；最长样本约 164 秒。即使功能断言通过，
稳定时延仍未达标。完整输入仍有数万字符，没有用本地缓存数据掩盖这个事实。

全仓 qguard 仍为 FAIL、0 分，最近一次扫描为 4964 条发现，包含构建目录的
重复副本；条目数不等于独立源码缺陷数。没有删除本地构建产物或关闭规则来换取通过。

详细原始产物保存在 ignored `outputs/agent-foundation-20261022/`；
Git 仅保存脱敏汇总，不保存配置、秘钥或原始对话。

这一轮没有重启正在服务的 8766 进程，也没有调用真实广告渠道 API。
回滚只涉及代码与评测配置，不需要恢复或重建数据库。

执行回收、来源快照和评测真实性已补强，不代表普遍语义理解、广告事实正确性、
生产恢复或稳定延迟都已达标。最终验证数据见
`agents/evals/advertising/evidence/foundation-quality-20261022.json`。
