# 历史消息回放修复

日期：2026-10-15。

## 问题与边界

原会话的内部协议记录仍存在，但历史接口将空正文的
`assistant(tool_calls)` 原样显示为助手消息；等待输入或 Tool 门禁终止时，
部分用户可见提示又没有作为最终回复保存，导致页面重开后出现空头像或缺少正文。

本次只调整广告应用的展示投影、最终回复持久化及前端回放。
不修改通用 Harness 生命周期，不删除模型协议消息，不重放任何广告操作。

## 实现

- 实时响应与持久化共用 `visible_run_reply()`，保存已脱敏的最终展示正文和状态。
- Harness 已写入原始消息时，只补充展示 metadata；没有助手行时补录最终回复。
- 历史详情和侧栏按 `turn_id` 投影为用户消息与最终助手回复，保留卡片和 Tool 状态，
  不把内部空消息、Tool JSON 当作聊天正文。
- 旧会话可从已保存的交互提示、错误与 UI 恢复展示，不直接修改旧数据库内容。
- 等待输入或确认不标记为失败；没有最终文字但有执行记录时，提示先核实结果，
  不将 Tool 成功标志解释为整个广告创建成功。
- 前端过滤无展示内容的空消息，回放错误样式和卡片，并移除实时回复的额外失败前缀。
- 应用补录消息使用 UTC 带时区时间，与 Harness 持久化时间一致。

## 实证

证据目录：`outputs/history-replay-e2e-20261015/`。

原会话 `66fb1903-bc67-4e2a-909d-d91cb4a2f899`：

- 修复前有 10 条原始协议消息，包括空助手消息和 Tool 结果。
- 修复后返回 6 条可见消息，用户和助手各 3 条，没有空助手正文。
- 模板提示恢复为“已加载所选模板，请确认草稿参数；尚未创建广告。”
- 失败原因恢复为“本次执行未完成：当时未开启真实写入，服务端已拦截该次操作。”
- Shopping 草稿仍保留原名称、预算、排期和商品账户引用。
- 浏览器刷新后重新打开原会话，DOM 断言确认 3 条非空助手正文；
  页面截图为 `restored-history.png`。

本轮没有调用 Provider 写接口，没有继续提交或确认创建。
服务重启后保留原用户模式；页面显示 live 不意味着旧失败请求被重新执行。

本次无存储 schema 迁移、无新权限、无 Provider contract 变更。
读取侧继续执行原用户与租户校验，展示正文和 UI 继续脱敏。
回退需恢复展示代码并重启服务；新增 metadata 不改变原始协议内容，
但旧展示代码会重新暴露空消息问题。

没有原文或可用执行证据的旧回复不能凭空恢复。服务在协议写入与最终展示保存之间
异常退出的回合只能依据已持久化证据提示实际状态，不能承诺完整原文恢复。
后续可沿用现有 trace 接口记录此类回合，不新增独立观察性链路。
