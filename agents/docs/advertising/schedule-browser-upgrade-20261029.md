# 定时任务分层浏览与分页（2026-10-29）

## 本次交付

定时任务首页只展示任务定义。点击任务名称或“运行实例”进入该任务的实例列表，再点击“查看结果”打开单次执行结果。首页不再混入所有任务的执行记录。

- 任务列表：按名称、执行指令搜索，按已启用 / 已暂停筛选。
- 运行实例：按实例 ID、Task ID、错误信息搜索，按执行状态、最近 7 / 30 / 90 天筛选。
- 两个列表分别支持每页 10 / 20 / 50 条、上一页 / 下一页、总条数和页数。筛选后回到第一页，返回上层保留原筛选和页码。
- 数据库按页查询，列表只返回摘要，不加载完整执行结果。编辑任务时单独读取完整指令，避免将摘要保存为任务内容。
- 正在排队或运行的当前页每 5 秒刷新；离开页面停止刷新。旧请求晚到不能覆盖新选择或重新打开已关闭的编辑器。
- 窄屏筛选项换行，实例表格支持横向滚动，分页保持可见。

## 接口与权限

沿用原有 Runtime → scheduling service → persistence store 边界，新增 `SchedulePageQuery` 和 store 的分页、单实例读取方法。分页内部固定表名与列名，输入全部作为绑定参数，搜索中的 `%`、`_` 按字面匹配。

```text
GET /schedules?page=1&limit=20&q=日报&status=active
GET /schedules/{id}?include_runs=false
GET /schedules/{id}/runs?page=1&limit=20&status=failed&since=...
GET /schedules/{id}/runs/{run_id}
```

分页响应包含 `pagination`（page、limit、total、pages、has_next、has_previous）。时间筛选统一转 UTC，起始包含、结束排除。原未分页请求的响应保持兼容；新的页面不再请求全局 `/schedule-runs`。

所有读取仍要求 `ads.read`。tenant、user 来自可信 principal，不能由请求参数改写；实例读取同时匹配 parent task、run ID 和身份范围。未修改广告写入、凭证或 live 执行门禁。
