# 工作区加载、管理交互与请求层优化

日期：2026-10-29。延续现有列表 → 详情 / 编辑布局，不改数据库、账号身份、模型配置或单 Agent Runtime。

## 已确认的问题与修复

| 问题 | 处理 | 验收边界 |
| --- | --- | --- |
| 模块逐个下载，网络失败后只有控制台错误 | 预加载最多 4 个脚本，仍按原依赖顺序执行；启动区显示进度，失败可从该模块重试 | 已执行模块不重跑；不使用动态代码执行 |
| 多处 JSON 解析失败返回空对象，看起来像数据消失 | 管理请求统一通过 `apiFetch`，覆盖响应体读取的超时和格式校验 | 普通读取 30 秒；写入与知识智能总结 120 秒；聊天 SSE 不套用该超时 |
| MCP、自建知识的旧请求覆盖新列表 | 共用目录加载状态，按目录和来源保存当前请求标识 | 仅当前请求更新列表或错误；不同来源独立维护状态 |
| 知识查询/目录刷新失败清空已有内容 | 保留之前的结果，紧凑状态条给出失败原因与重试 | 成功的空结果仍正常清空；加载、失败和空结果有不同文案 |
| 模型与密钥页签切换、关闭重开和刷新重填表单 | 草稿状态留在当前页面，刷新跳过未保存表单，提供显式放弃当前编辑 | 不将凭证草稿存入 localStorage/sessionStorage；刷新整页仍会丢弃未保存输入 |
| 设置读请求覆盖较新的保存结果，连续点击重复写入 | 读取合并、写入期间禁用控件、写入序号使旧读取失效 | 写入无自动重试；超时/无法解析写入结果时提示先核实 |
| 窄屏模型卡片两列挤压，字体偏小 | 模型列表统一单列，提高字号，沿用主题颜色 | 1440px / 390px，浅色 / 深色浏览器验收 |

## 架构与权限

- `chat-requests.js` 继续承担 HTTP 入口，统一 JSON 错误、超时和调用方取消；`serviceFetch` 保留给 SSE 等非 JSON 响应。
- 新增 `chat-catalog-loading.js` 只维护管理页请求状态，不缓存业务数据、身份或凭证。知识、Skills、MCP 仍调用原接口，不另建 Router 或执行器。
- `chat-settings.js` 负责自己的表单与提交生命周期；不改变后端加密存储、HTTPS 凭证写入限制或权限检查。
- 服务返回的参数校验错误只展示字段路径，不回显 FastAPI validation 的 `input` / `ctx`；网关 HTML 不直接展示。
- API URL、请求/响应结构、Tool contract、持久化 schema 均未变化。写操作未自动重放。

## 性能与验证

新增请求错误/超时、目录乱序/失败保留、设置草稿/并发写入、启动恢复回归。新案例先复现失败，再实现。

离线浏览器命令：

```bash
node scripts/advertising/check_workspace_resilience.cjs /tmp/workspace-resilience-final
node scripts/advertising/check_management_workspace.cjs /tmp/management-ui-catalog-fixture.json /tmp/workspace-round-all-management --check
```

需要环境中可用的 Playwright 与 Chromium。浏览器路由只返回本地静态文件或内存样例；不会连接服务端写入或广告渠道。模型保存测试使用内存响应，不修改真实模型配置。

在每个脚本注入 50ms 等待的离线实验中，同一份页面从串行下载的 1506ms 降到预加载的 458ms；27 次请求对应 27 个唯一脚本，没有重复下载。这只是模拟网络等待的比较，不代表线上 LLM 或广告 API 延迟。

全管理页验收覆盖知识阅读、Skills、MCP、模板编辑/草稿恢复、定时任务与运行结果、反馈审核、系统运维，并检查浅深主题及窄屏；另在原 8766 服务进行只读浏览器检查。最终 `make ad-agent-check` 通过：3302 项 Python 测试、编译、能力审计与知识检查；213 项前端测试通过，`git diff --check` 通过。原服务只读浏览器检查 6 组通过，页面错误为 0。完整记录见同名 evidence JSON。
