# 运行连续性与流式交互加固

本轮针对工具发现、长任务中止、结果判定和聊天传输的实际缺陷进行改进，保持单 Agent、
统一 Run Kernel 和 Tool executor 架构，不新增渠道路由分支。

## 已修复的问题

### 工具加载窗口

此前已加载工具达到上限后，整个 Run 不能再引入新能力。现在保持相同上下文容量，
用新发现的 schema 替换较早加载的 schema，需要时可重新搜索加载。精确工具名只返回
该工具，避免带入近似名称；namespace 使用既有的通用规范化规则。

每次最多 4 个结果，每个 Run 最多 6 次搜索，同时保留最多 8 个发现结果，并继续受
`max_tools` 限制。没有 schema 容量时明确返回 `capacity_limit`，不会谎报已加载。
源卸载、权限变化、契约变化或只读工具变成写工具时，会清除不再有效的加载记录。

`agent_discover_tools` 契约升级到 `1.1.0`，`replay_policy` 改为 `unsafe`：这是修改
当前 Run 加载状态的本地控制动作，不能用缓存结果代替执行。其 effect 仍为 `read`，
不访问 Provider，不获得任何写入权限，也不绕过账户、live、确认、幂等或审计门禁。

### 中止后的执行证据

在两个模型步骤之间取消、模型阶段被取消或丢失 Session lease 时，返回 envelope 保留
已经完成的 `tool_results`、调用计数、交互信息和运行信号。查询和写操作均覆盖。
原本需要核实的外部效果继续保持 `recovery_required / unknown`，不能因取消降为普通停止。
停止任务不会撤销已完成操作；后续核实可以使用这些结果中的资源 ID。

### 业务状态判定

executor 根据注册 Tool metadata 写入 `execution_role`。发现工具成功不会再把唯一一次
业务查询失败抬成 `partially_failed`；控制动作本身失败仍计入失败，所有记录仍留在轨迹中。
Provider payload 和模型参数不能自行标记为控制动作以掩盖业务结果。

### 聊天流传输

- 收到最终 `reply` 立即结束等待，不再依赖服务器关闭连接。
- 支持多行 SSE data、跨网络分片的中文/Unicode 与 CRLF、无内容心跳。
- 接收缓冲和单事件均限制为 4 Mi 字符；60 秒无网络进展时退出等待。后端每 15 秒心跳
  可维持正常长任务，不设置固定的任务总时长上限。
- EOF 没有最终回复、网络读取失败、格式异常与等待超时，均呈现为执行结果待确认。
  保留已收到的 Run ID，不自动重发 POST，避免重复提交广告操作。
- 已明确返回的服务端失败仍显示失败原因；部分失败也显示具体原因。HTTP 参数校验错误
  复用安全解析，显示字段路径，不回显被拒绝的凭证输入。
- 完成或异常后释放读取锁并终止客户端连接；这不意味着取消或回滚服务端操作。

## 验证

先新增回归复现：后端 8 个失败场景，前端覆盖完成后不关闭连接、断流、超时、多行 SSE
等问题；再修复实现。所有渠道结果使用本地 fixture，未调用真实广告 API。

验收用例位于 `test_run_continuity.py`、`test_runtime_discovery_integration.py`、
`test_chat_stream_transport.js`，并复用原有权限、并发隔离和 schema 边界测试。
完整验证数字与服务检查结果见同名 evidence JSON。

最终 `make ad-agent-check` 通过：3373 项 Python 测试、323 个 Tool 契约、85 页知识内容
以及编译和能力审计。前端 223 项测试、`git diff --check` 通过。专项 64 项测试覆盖的
发现与结果模块整体覆盖率 87%，其中 Runtime 工具发现模块 100%。

323 个工具的离线目录压测共 240 次，搜索与加载中位耗时 1.82ms、p95 2.054ms，
窗口最多 8 项。这里只衡量本地元数据处理，不包含模型或 Provider 延迟。

全仓 QGuard 未通过：771 个文件、4998 项发现、评分 0；发现数量与本轮开始前一致。
两个发现模块单独扫描均为 0 项发现。全量测试首次因旧 UI 源码字符串断言失败，
更新该断言并完成全量重跑后通过，流传输行为由 Node 用例实际执行验证。
