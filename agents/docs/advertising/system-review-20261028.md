# 广告 Agent 系统复盘与本轮优化

日期：2026-10-28。范围：单 Agent Runtime、对话上下文、Tool 执行、持久化、
知识与 Skill、评测证据。此次渠道能力核对使用仓库契约和已有证据，不调用真实广告 API。

## 当前能力与证据边界

- 单 Agent、Run Kernel、Turn Pipeline、Skill/Tool contracts 的边界已经建立；
  广告应用负责组合，真实外部执行仍经过统一 Tool policy。
- 本轮契约审计覆盖 321 个 Tool、6 个平台模块；Provider Source 审计包含 307 个 Tool。
  这是注册和契约覆盖，不是 321 个接口全部重新通过真实 API 验证。
- 知识库现有 85 篇文档，广告 Skill 包 31 个。知识检索回归为 65 个固定查询；
  对话回归集为 17 条，留出集为 12 条。固定用例通过不能替代真实用户准确率。
- 仓库 2026-10-26 的真实模型对话证据记录两次 14/15，通过项不同、失败项也不同，
  说明工具选择与调用数量仍有模型波动，不能宣称对话质量门禁已经稳定通过。
- 模板、蓝图、Provider live 账本、知识源及 Skill 均有版本化文件；本轮不清理、
  重建或替换业务数据库，不重新验证渠道写入。

## 本轮已修复的薄弱点

| 薄弱点 | 原行为与影响 | 本轮行为 |
| --- | --- | --- |
| 侧栏读取放大 | 每个会话额外加载最多 500 条协议消息，50 个会话会产生 50 次历史读取 | 优先读取完成 Run 时保存的可见消息窗口；没有窗口的旧会话使用一次受身份约束的批量查询，每会话最多 64 条近期记录和 1 条原始题目 |
| 旧会话预览与计数 | 有界历史可能被误当成完整消息数量，标题可能取到近期问题 | 旧会话批量读取保留最初题目；只读取部分历史时省略可选 `message_count` |
| 熔断跨身份传播 | 同名 Tool 的异常共享计数，一个身份的失败会阻断其他身份 | 熔断键绑定 tenant、user、execution mode 和 Tool；键使用摘要，不保存身份明文 |
| 冷却后并发突发 | 冷却到期时立即重置失败计数，所有请求同时进入依赖 | 同一熔断键只允许一个恢复探测；成功后关闭熔断，失败重新冷却，取消或本地容量拒绝会释放探测 |
| 熔断状态积累 | 失败键没有容量上限，恢复探测没有租约 | 最多保留 4096 个失败状态；恢复探测使用有期限的占用，异常退出不会永久卡死 |
| 对话协议被逐条裁剪 | 移除 user 后可能留下旧 Tool 调用片段；长回合可能丢掉当前任务 | 按完整用户回合移除旧上下文；保留当前任务和整个已执行批次，再在下一次模型准入时检查预算 |
| 超大当前回合 | 当前目标可能在后续模型调用前消失 | 明确返回 `model_input_limit_exceeded`；已执行 Tool 结果仍在 Run 结果和持久记录中，下一条新任务可正常开始 |
| 模型超限后的结果说明 | 非空的通用失败回复可能绕过已执行操作提示；成功查询也可能没有可见结果 | 输入/输出超限使用统一错误消息；成功只读结果可直接回显，通用失败回复遇到已有写入记录时明确提示先核对结果 |
| 约束复述被当成执行命令 | “创建要求”里的动词会强制模型调用 Tool，导致无意义的选账户或澄清 | 只对明确的执行命令强制写 Tool；复述依据当前有效约束回答，显式知识检索仍要求真实调用只读 Tool |
| 状态筛选改变原操作 | PAUSED、deleted、已删除等状态被当成新写操作；报表追问退回列表查询 | 区分状态描述与执行命令，筛选依据已发布的 action/resource/alias 沿用原查询类型；详情和知识问答不作为列表筛选的锚点 |
| 知识主题切换暴露渠道操作 | “从知识库解释”未被识别，模型可能看到无关渠道的写 Tool | 知识 Tool 声明来源别名；通用讲解选择器优先用户指定的检索来源，并排除明确否定的来源 |
| 知识 Tool 名称恢复不完整 | 模型使用不存在的知识 Tool 别名后，恢复逻辑仅覆盖网页搜索 | 唯一已注册检索 Tool 可使用其准确名称恢复，不转发被拒的别名或参数，不扩展授权目录 |
| Meta 报表遗漏账户字段 | 封闭 schema 没有 `account_id`，模型无法合法传入用户明确指定的账户 | 增加可选 `account_id`，复用既有 principal/白名单校验和可信 ToolContext 绑定；未放宽账户权限 |
| 长评测中断后缺少证据 | 整套评测结束前没有报告，运行时间较长时难以判断进度 | 每完成一例输出进度并原子保存有界证据；未完成套件明确标记失败门禁，写入失败保留上一份报告 |

此前的多模态修复继续保留：等待输入的 Run 可以恢复最近用户消息的附件；
同步和流式入口复用同一加载路径。恢复仍受租户、用户、会话、附件数量和大小限制。
这项能力限于等待输入的衔接，不代表任意多轮视觉历史都永久驻留模型上下文。

## 接口、权限与部署

- 持久化 port 增加 `list_conversation_preview_messages`，由现有 repository/facade
  实现批量预览；SQL 留在持久化层，应用服务只消费 `ConversationMessagePage`。
- `/sessions` 的分页、标题和预览字段继续使用现有协议；不完整预览不返回精确消息数。
  完成 Run 的展示缓存可能比正在执行的原始协议消息晚，侧栏展示最近完成的可见内容。
- 熔断是可用性控制，不是执行授权。Schema、principal、live、账户范围、确认、
  幂等、审计和未知写入恢复继续由既有 policy 负责。
- 知识检索 Tool 更新为 `1.0.1`，只增加来源别名，输入输出和权限不变；
  契约快照同步更新。讲解场景只缩小可见 Tool 集，不授予新的渠道权限。
- Meta Campaign 报表 Tool 更新为 `2.0.1`，增加可选账户字段，不增加必填项，
  不改变 Provider HTTP 方法。契约明确目前不支持状态筛选，不能声称已按状态过滤。
  部署和回滚应同步 Tool 定义与契约快照；没有数据库迁移，也不需要删除业务数据。
- 无数据库 schema 迁移。部署时需加载新后端代码；回滚代码即可，聊天记录和业务资产
  不需要回滚或删除。新增 port 的其他自定义后端需实现同一批量读取契约。
- 继续使用现有安全事件与 Run 记录；此次没有引入新的观察性服务依赖。

## 尚需加强的方向

1. **语义准确性与能力发现**：Tool metadata、LLM 意图目录和动态发现已存在，
   但通用选择器仍有大量词法规则。后续应把未知表达、跨主题切换、短追问和能力遗漏
   放进持续留出评测，优先使用声明的 intent/resource/traits，减少继续增长的短语分支。
2. **同一长任务的渐进式证据压缩**：本轮保证超限时安全停止并保留当前目标；
   尚未实现能保留 ID、数据口径、失败边界和执行事实的通用增量摘要。
   后续摘要必须有来源引用，不能把旧结果或旧账户当成新轮次授权。
3. **真实用户质量指标**：已有反馈、回归导出和阶段耗时；仍需积累足够的真实模型样本，
   分开统计首次工具命中、澄清次数、无结果原因、首个可见输出时间和成功率。
   不能只用本地单测数量或固定查询命中率评价业务准确性。
4. **知识与程序性记忆维护**：应持续核对官方来源版本、更新日期和已验证案例适用条件。
   从失败中吸收的规则应进入可评测、可回滚的 Skill/知识版本，不能自动变成执行代码。
5. **核心模块维护性**：全仓静态质量门禁仍有历史债务。应按 Tool selection、执行准入、
   结果投影等职责逐步拆分大模块；本轮用相同扫描规则比较变更，要求不增加静态发现。
6. **部署规模与渠道边界**：当前 SQLite 部署仍按单进程使用；本地负载测试不证明
   多用户生产容量。三渠道具体广告类型以已有 live 证据、模板和平台限制为准，
   本轮不更新真实 API 通过状态；DV360 深度写入仍不属于当前验收范围。
7. **查询条件表达与专业内容准确性**：Meta Campaign 报表目前只声明账户、Campaign ID、
   日期和分页等条件，没有状态筛选参数；此项尚未打通，不能将单纯调用报表 Tool
   记为“已完成 PAUSED 筛选”。固定留出断言主要检查 Tool 及少量文本条件，
   尚不足以判断整段广告知识是否严格区分平台概念，后续需补参数级和专业内容评测。

## 验证记录

- 定向回归已通过：侧栏缓存/旧会话批读、跨租户用户隔离、存储失败后重试、
  熔断并发恢复/探测租约/容量上限、完整回合裁剪及溢出后恢复。
- `make ad-agent-quality-delta`：相对 HEAD 扫描 24 个变更 Python 源文件，
  原有发现 445 条、当前 445 条、新增 0 条。此项不代表全仓质量门禁通过。
- 全仓 qguard：757 个文件、4993 条发现，门禁仍失败；数量与此前基线相同。
- 新熔断实现的行覆盖率为 100%，批量预览实现为 95%，两者合计 99%；
  这不是全系统覆盖率。
- 内存 SQLite 合成侧栏对比：50 个会话、每会话 100 轮、共 10000 条消息，
  每条路径采样 5 次。旧路径 51 条 SQL、P50 99.770 ms；展示缓存路径 1 条 SQL、
  P50 2.815 ms。标题和预览一致。这不证明实际磁盘数据库或生产并发容量。
- 无网络 Harness 初始化及一次只读调用的 10 次 smoke benchmark 全部成功，
  P50 1068.16 ms、P95 1539.22 ms；该数值包含测试 Runtime 初始化，
  不包含真实模型或渠道耗时。
- 当前语义修复已通过包含知识检索、状态筛选、操作否定、账户上下文和
  通用能力发现的 160 项定向回归。增加 Meta 报表账户字段与 3 项专门回归后，
  最终 `make ad-agent-check` 完整通过：3161 项测试、编译、Tool 契约审计、
  321 个 Tool 的快照校验，以及知识库质量与性能检查。
- 本轮真实模型留出评测使用 `agnes-3.0-flash`（`apihub.agnes-ai.cn`），
  初测 12 个案例包含 29 轮用户输入，结果 8 通过、4 失败。渠道使用离线替身，
  不作为真实广告 API 成功证据。初测报告原样保留。
- 首轮定向复测 4 例中 1 例通过：TikTok 列表筛选恢复成功；预算撤销复述、
  报表筛选和知识库切换仍失败。进一步修复后，预算撤销原案例单独复测通过，
  没有 Tool 调用，也没有重新询问账户。
- 报表筛选原案例已选中正确的 `meta_get_campaign_report`，实际状态是
  `awaiting_input`，回复要求选择账户。该案例虽然说“沿用当前已选择的账户”，
  但评测创建的是全新 Session，之前并未真正提供或选择账户，因此不能要求执行成功。
  原案例及其断言不修改，保留失败。显式补充账户的对照案例仍失败，进一步定位到
  Tool schema 遗漏账户字段；已修复该契约，离线 Runtime 回归验证授权账户成功、
  越权账户失败，相关报表回归 22 项通过。随后新增的一轮真实模型报表查询也通过，
  成功执行一次离线报表 Tool，验证模型可以传入账户字段；此例不含状态筛选。
  没有将原来的状态筛选失败记录改成通过。
- 知识库切换原案例最后单独复测通过，实际成功调用一次 `agent_knowledge_search`，
  无渠道账户读取。该批共 2 例，另 1 例为上述修复前的报表对照案例，整体 1 通过、1 失败。
  预算撤销、TikTok 列表筛选和知识库切换分别取得通过证据，不能拼接成一次完整套件全通过。
- 每例耗时包含其完整多轮历史，不能当作单轮聊天延迟；此次耗时主要在模型请求。
  单次或分批复测通过不代表整套留出集在当前版本稳定达到 12/12。
