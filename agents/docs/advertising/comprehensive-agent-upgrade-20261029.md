# Agent 连续性、上下文与优化复盘升级

本轮围绕多轮准确性、工具扩展、Prompt 负载、运行恢复和广告优化复盘进行增强。
继续使用单 Agent、Run Kernel、现有 Tool Registry 和持久化接口；没有新增渠道 Router，
也没有把用户 Skill 变成可执行代码。验证数字见同名 evidence JSON。

## 需求、落点与验收

| 改进 | 实现边界 | 验证 |
|---|---|---|
| 用户修改要求后不保留冲突旧值 | `semantic_constraints` + Session store + 两个约束 Tool | 来源原文、替换/撤销、版本冲突、异常持久化数据、保存失败不修改内存、身份隔离 |
| 动态发现工具后同步 Skill 指导 | Harness 可选 `build_tool_context`，应用 `selected_context` | 工具集合变化重新组装、Run 内缓存、结束清理、上下文预算重新计算 |
| 降低首轮 Prompt 负担 | 初选 schema 预算、Skill 去重和限额、能力目录压缩 | 广告蓝图入口保留、完整流程与明确多渠道查询保留、离线实际 payload 对比 |
| 长任务断线后恢复完整结果 | 有界事件游标分页 + 浏览器只读恢复 | 600 条终态事件、跨会话响应丢弃、回复去重、延迟入库、网络失败上限 |
| 广告优化建议能持续复盘 | 独立服务、存储 Repository、三个本地 Tool | 目标与身份范围、去重、CAS、live 审计、回读值、观察成熟度、冷却期 |
| 评测能发现波动 | 重复采样、独立 case 数与样本数分开；前端测试进入 CI | runner 单测、holdout 声明验证、Node 回归 |
| 知识维护反映变化速度 | freshness 按知识元数据确定周期，新增复盘案例与 Skill | API/政策与基础知识分级、全库审计和检索回归 |

## 行为与契约

新增约束 Tool 为 `agent_get_conversation_notes`、`agent_update_conversation_notes`。
修改通过 `expected_revision` 校验；新增、替换、撤销必须逐字引用当前可信用户消息，
不能把助手总结、工具返回或上传文件变成授权。语义关联由模型按 Skill 判断，服务端只校验
来源、旧记录 ID 和版本，不在中心路由追加预算同义词或渠道分支。最多八条有效语义约束、
十六条修订历史；旧有简要用户约束保留兼容。

新增复盘 Tool 为 `agent_create_optimization_review`、`agent_get_optimization_review`、
`agent_update_optimization_review`。读操作要求 `ads.read`，本地写操作要求 `ads.plan`；
记录限定当前可信 tenant/user/account，不能覆盖其他用户的数据，也不授予外部修改权限。
同一用户、账户、资源和字段的重复建议去重；它不是跨用户的企业级广告操作锁。

复盘顺序为 `proposed → executed → verified → reviewed`。执行证据来自当前身份的既有
Tool 审计：成功、live、目标和参数一致，并且发生在建议之后；回读必须使用 write Tool
声明的 `readback_tool`，验证同一目标与预期值。无法唯一定位的同轮同名调用会明确拒绝，
不会猜测证据。不发起新的 Provider 请求，不因用户或模型说“已经完成”就更新为已执行。

复盘的基线和结果明确标注为用户提供的观察数据。两者指标、币种、时区、归因天数与窗口长度
必须一致，基线须早于执行日期，观察须在执行后，日期按指标时区判断。观察至少七天，
窗口结束再等待归因天数和七天回补。这个保守门槛是本系统规则，不是平台 SLA。
零基线不计算相对变化；前后对比不输出因果收益结论。完成复盘且冷却结束后可显式开启下一轮。

首轮通用业务候选默认最多八个、约 18k schema 字符；Harness 基础控制工具另行保留。
必要的蓝图入口、明确流程和多渠道范围
优先保留，可能超过此软限额。完整 schema 不截字段，其他注册工具仍可通过发现工具加载。
Harness 原有 `build_context` 适配器保持兼容。应用按实际可见工具更新 Skill 上下文，避免
重复注入已经由 Harness 选择的内置包；Skill catalog 限制为六个、6k 字符。

## 失败恢复和部署

Run events 增加 `has_more`、`next_after_seq`，`latest_seq` 表示本页交付位置。
终态也会继续翻页直到读完。断流只 GET 恢复状态与历史回复，不自动重发 POST；遇到
403/404 停止，持续网络错误或缺少最终回复最多六次恢复尝试后提示刷新。切换会话使旧请求失效。
停止恢复不代表服务端任务停止，也不代表外部操作回滚。

数据库 schema 从 27 加到 28，仅新增 `optimization_reviews` 表与索引。SQLite 与已有
MySQL adapter 共用 Repository 接口和迁移机制；本轮不迁移部署数据库，也没有真实 MySQL
实例验证。Session 约束保存在已有 metadata 中，旧数据无需改写。

部署继续使用 `agents/ad_agent/config.test-live.yaml`、`agents/ad_agent/ad_agent.db`
和 `0.0.0.0:8766`。重启前使用 SQLite backup API 备份到 Git 工作区之外，并核对用户模板
和最近会话 ID。回滚需一起还原代码、静态资源、Skill 与 Tool 快照；数据库降级使用受保护的
升级前备份，切勿直接覆盖仍在运行或已经产生新记录的数据库。先保存新增记录并停服务再恢复。

观察性沿用现有 Run/Turn ID、审计、知识交付记录和 Prompt 预算字段，无新增监控基础设施。

## 验证范围与限制

最终 `make ad-agent-check` 通过：3405 项 Python 测试、229 项前端测试、328 个内置 Tool
契约和 86 篇知识内容检查；知识审计为零错误、零警告。新增模块专项 56 项测试，合计行覆盖率
91%。增量 QGuard 未新增发现；全仓扫描仍未通过，遗留项数量见 evidence JSON。

离线 Prompt 采样中，模板、创建、连续追问的序列化字符分别减少约 51%、56%、65%；报表
减少约 10%，知识问答减少约 8%，问候基本不变。多渠道任务和完整蓝图不会为了压缩而丢弃
必要入口，因此这些数字不是所有问题都能达到的固定降幅。

原服务已重启并监听 `*:8766`，`readyz` 返回 200；五个新 Tool、两个对应 Skill 和前端恢复
代码已加载。schema 已升级到 28；全部 513 个会话的数量、最近 200 个会话 ID，以及 14 个
用户模板 ID 均与升级前一致。配置化服务共有 354 个 Tool，内置离线契约快照覆盖其中 328 个。

所有渠道执行验证使用离线 fixture，本轮未调用真实广告 API。Prompt benchmark 捕获真实
组装消息和 schema，但固定回复、不调用外部模型；字符减少不能直接换算为 token 或延迟提升。
Skill-up 的 CI 工作目录已修正；本机未安装 CLI，真实模型重复评测尚未运行，因此不能把
离线通过当作线上语义准确率证明。保留发布门禁的独立 case 数要求，不把重复三次当成三倍覆盖。

全仓 QGuard 存在历史债务；本轮同时运行全仓和增量门禁，在证据文件中分开报告，不能用
增量通过代替全仓通过。真实 Provider 的历史有限验证状态也保持原样。
