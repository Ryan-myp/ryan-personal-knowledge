# Prompt 构造优化（2026-10-28）

本轮只修改模型输入投影和上下文选择，不调用真实模型或广告渠道 API，不变更业务数据、
执行权限、模型配置或服务端口。保留此前工作区中的未提交修改。

## 调查结果

实际调用链为 Harness 固定系统提示 → 应用业务上下文 → SkillCatalog → 有界历史，
工具 schema 另外放在模型 API 的 `tools` 参数中。总输入不能只统计消息正文。

- 固定系统提示与广告应用提示合计约 11K 字符，包含权限、事实依据、多轮目标和输出边界；本轮保留。
- Skill 选择把参考文档中的泛词也视作相关性，多个场景加载 8 个 Skill、填满 12K 字符。
- 同一工具 schema 同时服务 UI、解析器、executor 和模型，模型收到大量展示条件、选项标签和表单布局信息。
- 业务上下文无条件加载创建蓝图，问候和只读报表也携带创建说明。
- 已选模板的 selection JSON 在结构化参数和流程说明中重复出现。
- `tool_prompt` 文本并未渲染给模型，却参与业务上下文的 20K 总预算，会挤占记忆和历史证据。

## 已落地

1. **工具 schema 使用通用投影。** 删除 UI 展示注解，隐藏服务端管理字段，保留字段名称、枚举、
   类型、长度/数量限制、lookup 来源和依赖。支持嵌套对象、数组、组合条件和 `$defs`；
   `default`、枚举值和名为 `ui_hidden` 的业务字段不会被当成注解误删。
   原始 executor schema 不修改，JSON Schema 顶层约束也不再被一律丢掉。
2. **输入预算与投影一致。** Harness 在计算总输入上限时使用相同的模型工具投影，避免按照
   UI 的完整元数据提前裁掉仍可容纳的历史。SDK 调用前仍有最终大小校验。
3. **Skill 正文按相关性选择。** 降低普遍出现在参考文档中的词的作用；名字命中、Skill 声明的
   literal triggers/aliases、当前 Tool 的 `skill_refs` 优先；`always_on` 不再被普通匹配挤掉。
   弱相关候选不自动填满剩余预算，单 Skill 正文与引用合计最多 3600 字符，总预算仍为 12K。
   来源范围和绑定集合都进入缓存键；匹配频率只在获准来源内计算。
4. **创建上下文按需提供。** 仅在业务上下文选出的 Tool 声明创建写入时加载通用蓝图。
   用户已选蓝图/模板仍通过 `creation_selection` 直接传递预填值、父子顺序和 lookup 要求，
   流程说明引用这一份 JSON，不再复制。
5. **修正无效预算消耗。** 从业务上下文中去掉不发送的 `tool_prompt` 副本，保留记忆、会话摘要和证据的预算。

`build_tool_context` 是 SkillCatalog 的可选增强接口；旧 catalog 继续使用 `build_context`。
Tool 选择集合没有缩小，完整能力目录、工具发现入口和原执行校验链路保留。
未引入渠道名或用户问法补丁，也未新增 Router 或 Runtime。

## 离线对比

测量真实 AdvertisingComposition/Harness 构造出的消息和 SDK Tool schema，使用内存数据库、
合成 principal、离线 Tool Source 和捕获模型，socket 连接被禁止。
固定回复仅用于推进会话，不执行工具。这里是**序列化字符数，不是 token、费用或响应时延**。

| 场景 | 优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 问候 | 25,565 | 23,412 | 8.4% |

| Google 模板目录 | 118,170 | 93,531 | 20.9% |
| Meta 创建请求 | 107,748 | 92,253 | 14.4% |
| 创建后追问 | 140,268 | 122,090 | 13.0% |

7 个场景的 active Tool 名单前后一致。报表样本由 8 个 Skill 缩到 3 个，Google 模板样本
缩到对应渠道 Skill；模板预填、知识送达凭据和权限边界另有行为测试，不靠输入变短推断正确性。

## 验证与限制

测试先复现问题，再实施修改。第一轮新增测试为 9 failed / 11 passed；修复后 118 项定向测试通过。
全量回归还发现了渠道名字权重过高、遗漏配套诊断 Skill 的问题，已通过包内声明的触发条件修正，
保留原跨业务验收断言，未放宽验收标准。

最终 `make ad-agent-check` 退出码 0：**3267 passed、1 warning，测试耗时 291.97 秒**。
编译、321 个工具契约快照、Provider 能力审计、知识质量/检索检查、`git diff --check` 均通过。
定向覆盖率中，本轮 schema 投影模块为 98%、SkillCatalog 为 81%，与 metadata 模块合计 82%。
增量 QGuard 已通过（45 个变更 Python 源文件），新增 findings 为 0。
全仓 QGuard 仍失败（762 文件、4990 findings），不能据此声称全仓质量达标。

没有运行真实模型的答案质量/准确率对比，也没有测量服务端 token 缓存命中或用户端响应时延。
部分请求仍一次召回 28–32 个工具，schema 仍是主要体积来源；后续可在已有工具发现机制中
做任务相关的分阶段加载，并用多轮执行评测验证完整性。双通道的业务 Skill 指导与 Harness
SkillCatalog 仍有进一步统一空间，本轮没有为了去重而删除未证明重复的 SOP。

无需数据库迁移、凭证调整或新服务。回滚只需恢复本轮相关 Python 变更和测试；不应整树
reset，因为工作区包含此前迭代内容。运行服务需重启才能加载；本轮未重启、未提交或 push。
后续观察性接入可复用现有模型输入指标与本轮基准脚本，按字符构成记录，禁止记录原始 Prompt 或凭证。
