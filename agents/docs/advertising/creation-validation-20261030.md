# 创建参数链路第二轮补齐

本轮在 `7932e9f` 的三渠道目录、预设和模板版本能力之上，补齐共同使用的字段校验、
页面输入和模板权限边界。没有新增渠道 Router、Provider 直连入口或第二套 Runtime。

## 参数与页面

- 向导按 JSON Schema 的 `properties` 逐层解析嵌套 Tool 字段，保留类型、数值限制、
  枚举及资源查询 metadata；未知路径不回退到整个父对象。
- 对象的 `required` 子字段数组不再被误当作父字段本身必填。
- 无枚举、无 lookup、无显式高级编辑模式的字符串数组使用逐行输入；对象数组、
  多选枚举、资源选择和显式 JSON 控件保持原有表示。API 字段名和值不做中文翻译。
- Runtime 的 Blueprint 评估与对话创建卡使用同一个已有 Tool validator，在填写阶段
  检查已提供且可见的字段，包括类型、范围、长度、数组数量、重复项、对象必填子字段、
  未声明子字段和格式。缺失字段仍由原有联动规则判断；部分草稿可以继续填写。
- 单值 `derived_readonly` 字段在条件联动前进入评估副本，修复 Search 广告格式尚未
  参与判断、标题字段被误隐藏的情况，不修改调用方草稿。
- 可选数组不会仅因只有一个候选项就被自动代选。修复 Meta 区域声明被自动填成
  单个字符串的问题；显式 Blueprint/Tool 默认值保持不变。
- 字段错误以中文显示在对应控件下，修正后清除；设置 `aria-invalid` 与错误关联。
  诊断只展示固定类别和数值限制，不转发 validator 中可能含输入值或未知键名的原文。

接口仍为 `POST /creation-blueprints/{id}/evaluate`，新增可选的
`fields[].validation_errors: string[]`。`invalid_fields`、`state`、`ready` 保持原结构，
但不合规的已填值不再被标成就绪。对话创建卡也携带同样的字段诊断。
这不替代提交时的完整 Tool 条件校验、账号资源校验或执行授权。

## 权限与验证记录

- 模板 create/update 对目标账号做范围校验；update/delete/duplicate/apply 同时检查
  原模板的访问范围。不能在权限收窄后，仅凭旧模板 ID 修改、复制或应用不可访问的模板。
- 身份仍来自 trusted principal；接口权限仍为 `ads.read` / `ads.plan`。无法访问的既有
  模板保持 404，新建或重新绑定不可访问账号返回 422，失败不改变模板、默认标志或使用次数。
- 验证账本容忍无效 identity、coverage 和 legacy resources；读取失败或不完整记录
  不证明已验证。操作展示有上限，截断部分显式保留未知状态，避免遗漏后面的失败后仍显示通过。
- 日期仅接受可解析的 ISO 值，不能借日期字段把任意账本文本带到页面。

默认 dry_run、测试账号写白名单、其他账号只读、live 开关、确认、幂等和审计均未放宽。
本轮没有发起真实广告或模型请求，也没有把目录覆盖升级为 live 成功证明。

## 恢复与部署

无需数据库迁移，不覆盖用户模板、历史 Blueprint、会话或定时任务。已有草稿重评估后
可能出现以前漏检的错误；原值保留，用户可以就地修正。新增诊断是加法字段，旧客户端
可以继续忽略；回滚仅回滚代码，不恢复整库，不建议回退账号范围保护。

沿用已有结构化执行审计和返回字段，本轮不要求新增观察性基础设施。
