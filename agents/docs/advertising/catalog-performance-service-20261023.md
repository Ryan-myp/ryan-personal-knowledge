# 目录上下文、服务托管与质量增量检查

## 变更边界

1. 通用 ToolSelector 从发布者元数据识别明确的本地目录读取请求：
   `read`、`local`、`catalog` 和已声明 alias。目录候选不再混入同渠道的大型写入 schema。
   新增合成文档渠道回归，证明没有增加 TikTok / Google / Meta 问句硬编码。
2. 广告应用对目录操作保留身份、账户、当前表单和会话记忆；不注入无关的专家、
   蓝图和知识片段。普通知识查询与能力介绍仍使用原有上下文路径。
3. 部署层新增当前用户的 macOS LaunchAgent 控制器，不进入 Agent Tools，
   不向模型开放本机进程控制。继续使用仓库 Python 包装器和单 Worker。
4. 两个独立框架 wheel 排除嵌套 `build` / `dist` 包。测试主动植入构建副本后检查 wheel。
5. 新增 qguard 增量检查，使用原分析器和原规则，对比 `HEAD` 与当前改动。
   以规则、等级和源码行哈希匹配既有告警，重复增加同类问题仍会失败。
   报告不输出源码片段、密钥值或原始分析器上下文。

无数据库迁移，不调整默认 dry-run、测试账户、权限、live 白名单、确认、幂等或审计。
没有另建 Agent / Router / Run 生命周期。

## 启动与恢复

```bash
make ad-agent-service-install
make ad-agent-service-status
make ad-agent-service-restart
make ad-agent-service-stop
make ad-agent-service-uninstall
```

默认监听 `0.0.0.0:8766`。配置及数据库使用明确的原有绝对路径。
plist 不复制 API Key、token 或 live 开关，服务沿用既有 `.env` 和加密设置。
plist、标准输出和错误日志均使用私有文件权限。

安装时遇到已有监听必须显式接管；控制器验证用户、工作目录、应用模块和端口。
其他项目或其他用户的进程不会被终止，同名的外部项目 plist 不会被覆盖。
默认同端口接管时，原服务释放端口后才启动新服务，避免 SQLite 由多个服务实例共同运行。

LaunchAgent 在当前用户登录后自动启动、进程退出后自动恢复，不代表登录前的系统级服务，
也不保证笔记本休眠期间可访问。没有通过整机重启来验证登录启动。

本机已在空闲状态执行进程终止测试，新 PID 约 8.45 秒后恢复，健康检查通过，
数据库记录数量前后一致。没有执行广告写入；这不是进行中 Provider 写操作的自动续跑证明。
Run 故障恢复仍使用原租约、持久化状态和显式恢复规则，不盲目重放广告写入。
重启前尚未提交的签名确认和 lookup 凭证应重新获取，不能据此恢复旧写入授权。

停止或卸载只影响托管进程，不清空日志、模板、聊天、素材、知识或数据库。
回滚应用代码时保留原数据文件。需要退回手工启动时，先卸载 LaunchAgent，避免重复监听。

## 性能证据边界

此前一次流式目录对话的首轮请求为 13 个 Tool、73892 字符；
本轮非流式复测为 2 个 Tool、33453 字符，首轮输入减少约 54.7%。

但是该非流式复测总耗时为 110.92 秒，两次上游调用为 84.02 秒、25.70 秒。
这不是同负载的受控性能对照，也没有证明端到端时延改善。
另一次使用页面相同 SSE 入口的复测为 155.62 秒，两次上游调用为 95.12 秒、59.33 秒。
两次新复测均成功返回本地模板，均只提供 2 个 Tool。
不能把输入减少、本地检索速度或固定桩测试时间当作免费上游模型的实际响应时延。
仍需继续处理模型侧排队、推理时延及目录交互所需的模型轮数。

真实模型复测只调用本地模板 Tool；没有确认、创建、更新或查询广告 Provider 资源。
