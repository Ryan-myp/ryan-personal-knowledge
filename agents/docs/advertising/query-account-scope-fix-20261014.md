# 无预填账户的连续对话查询修复（2026-10-14）

## 原因与旧验收缺口

用户先查询 Meta 账户，再追问该账户的 Campaign 列表时，模型已正确传入
`account_id`，当前身份的授权校验也通过了。执行适配器却只读取
`ToolDefinition.scope_fields`，没有使用权限校验侧的账户字段回退规则。
内置 Tool 没有显式声明该字段时，Handler 收到的账户为空，即使 Client 已配置，
也返回离线 fixture；数据边界随后将其拒绝并误报为 Provider Client 未配置。

上一轮 28 个成功回合预填了 HTTP 顶层账户并限制了渠道 Tool，因而绕过了这个缺陷。
旧验收说明已补充这一限制，不能继续将它当作页面原始对话链路的完整证明。

## 实现边界

- 权限校验、执行和读取重放键共享 `shared/domain/account_scope.py` 的账户解析，
  使用 Tool 声明的 scope fields 或广告域账户别名，并保留渠道别名与多账户隔离。
- 实际账户写入请求级 `ToolContext`，不临时修改共享 Session；查询结果的参数选择
  凭据也使用该请求上下文，校验签名时仍须匹配实际账户。
- 成功的 live 读取只记录有界、按 namespace 分开的查询账户候选。通过现有
  Session metadata 存储接口持久化和恢复，不新增 SQL 或账户身份来源。
- 查询候选仍须通过每次调用时的当前 principal/configuration 授权，不自动选择
  创建、更新、删除的账户，不从失败或模拟结果建立候选。
- Tool 选择器也使用已获准的查询账户作为渠道提示，避免短追问退回全部渠道后
  丢失相关 Tool。明确切换渠道优先；歧义或已失效的授权不提供推断。
- 模型收到有界的、principal 与配置交集内的只读账户候选，避免在首次账户查询时
  猜测 ID。候选不代表 Provider 连通性，也不是写入授权。
- `tiktok_list_accounts` 不再要求另外选择一个标量账户。其显式账户数组仍必填，
  Handler 在调用 Provider 前按当前授权集合校验；单 Tool 契约版本为 `1.3.1`。
- REST 和 SSE 在模型限流、超时等没有文字回复的失败情况下返回明确说明；
  不将失败解释成无数据，已有执行记录时提醒核实而非直接重放写操作。

通用 Harness 的 Run、身份、租约、确认、幂等和审计链路没有被替换。无广告数据迁移，
没有开启 live 写入门禁；回滚须同时恢复 Tool 快照与实现并重启服务。

## 真实验收

主服务 `127.0.0.1:8765` 的 `/chat/stream` 请求只有自然语言、Session ID 和 dry-run
模式，没有 `account_id`、`platform_params` 或 `tool_allowlist`。

| 渠道 | 用户确认的测试账户 | 账户数 | Campaign 列表 | 已选 Campaign 下的组 | 已选组下的 Ad |
|---|---|---:|---:|---:|---:|
| Meta | `2806375919473667` | 1 | 5 | 1 | 1 |
| Google Ads | `9055507554` | 1 | 5 | 2 | 1 |
| TikTok | `7397068114548195329` | 1 | 5 | 1 | 2 |

每个渠道六轮：账户列表、Campaign 列表、单个 Campaign、组列表、Ad 列表、单个 Ad。
18 个验收回合均返回成功的 live 结果。列表的 5 是请求上限内返回数，不是账户总数。
TikTok Ad 详情另外读取了视频、图片和 Identity，不能声称每轮仅有一次 Tool 调用。

原始失败保留：TikTok 首次目录被错误的单账户门禁拦截；一次 Ad 查询遭遇模型
限流，尚未执行广告 Tool；另一次因渠道提示丢失查询了错误资源。修复后继续同一
会话验证，失败和错误资源回合不计入 18 个成功验收回合。

还直接操作了页面：使用用户截图的原句先查 Meta 账户，再查 Campaign，得到
100 条真实记录；继续查询单个 Campaign，并在服务重启后追问 Ad Set、Ad 列表，均成功。
最后一次页面 Ad 查询的参数选择凭据也已核对：绑定账户为 `2806375919473667`，
不是空账户；签名验证和跨账户拒绝由对应回归用例覆盖。
这不是替换模型或预填参数的页面测试。

本地证据位于 `outputs/query-scope-ui-20261014/`：`summary.json`、各回合 SSE JSON、
保留的失败回合、`meta-page-proof.png` 和检查日志。测试产物与凭证不纳入提交。
