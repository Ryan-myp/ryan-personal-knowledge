# 管理工作区与模板体验改进（2026-10-29）

## 结果

- 管理页使用主内容区，侧栏保留全局导航。模型与密钥、系统运维位于模板管理下方、最近对话之前。

## 模板恢复与契约

旧服务进程加载新版通用模板时，仍要求所有内置模板必须有 account_id，模板接口因此返回 503；旧前端又将异常转换为空列表，造成模板丢失的观感。

沿用原 LaunchAgent、配置和数据库重启后，8766 回读得到 **32 份可见内置模板（14 份账户模板、18 份通用起步模板）**、31 个蓝图。文件中还保留另外 2 份当前账户范围不可见的 DV360 模板；未清空或重建数据库。

通用模板的 `scope_type=general`、`verification_status=dry_run_only`，不能绑定账户或声明真实创建验证。展示仍遵守 principal 的渠道和账户范围。目录中的广告类型与蓝图改用显式 ID 关联，避免相近词误匹配；增加 TikTok 常规单图、单视频蓝图，并修正 Google starter 的广告类型默认值。

这些是目录和字段契约验证，不代表所有广告类型已经完成 live 验收。创建契约审计仍报告 6 处结构化引导缺口、11 处保留高级编辑的开放 payload。
