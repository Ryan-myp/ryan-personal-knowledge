# 广告知识讲解

本 Skill 固化广告知识问答的方法，不承载平台事实、API 枚举或账户数据。事实来源仍以相关 Wiki、渠道 Skill 和当前获准的只读查询为准。

## 回答流程

1. **识别问题类型。** 判断用户是在问概念、机制、差异、选型还是具体账户状态；纯知识问题不触发账户查询，账户现状和报表问题交给对应只读 Tool 与诊断 Skill。
2. **先给结论。** 用一到三句话直接回答，再按问题需要解释层级、机制、选项差异或因果关系。
3. **贴合用户场景。** 只展开与提问相关的渠道、广告类型和决策分支；多个选项需要比较时使用短表格，流程复杂时再画图。生成 Mermaid 时，每个连线端点都使用明确的节点 ID，节点文案写成 `NodeId["标签"]`；不要把裸引号文本直接接在箭头后。
4. **说明依据和边界。** 区分平台事实、运营建议、推断和待当前账户/API 版本确认的配置；没有来源的数字、硬性门槛和平台承诺不写成事实。
5. **给出可执行的理解或下一步。** 信息足够时给出适用条件和风险；缺少会改变答案的关键条件时，只追问最必要的一项。
6. **收束在用户的问题上。** 不附加无关的产品能力介绍、Agent 自评或泛化的营销建议。

## 检索和证据

- 概念讲解可以使用当前注入的检索片段；用户明确要求查资料或检索时，通过当前注册的知识检索 Tool 获取依据，不以直接生成长篇说明代替检索动作。需要最新外部信息时再用已注册的网页工具补充。
- 知识检索不需要广告账户。不得为了查术语或机制先要求选择账户、读取 Campaign 或查询素材。
- 对比产品或系统角色时，每项事实都要有当前片段支持。来源提到了多个产品，不代表它们具备相同职责；没有支持的产品能力不外推，也不编造引用。依据不足时缩小结论或补充检索。

按需读取[回答结构与证据边界](references/answer-structure.md)。保持 Skill 为 advisory 指引；查询、执行、权限和账户范围始终由当前 Runtime 与注册 Tool 决定。
