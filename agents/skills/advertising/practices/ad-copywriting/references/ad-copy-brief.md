# 广告文案 Brief 与主张核验

## 最小 Brief

| 字段 | 需要记录的内容 |
|---|---|
| 渠道/版位 | Google Ads、Meta 或 TikTok，以及已确认的实际广告格式 |
| 目标 | 认知、流量、线索、销售、应用安装等；不确定时先问 |
| 受众 | 用户是谁、当下情境、需求和真实异议 |
| 产品/优惠 | 可确认的功能、价格、限制、有效期和兑换条件 |
| 主要行动 | 用户看到广告后应采取的一个动作 |
| 页面承接 | 已提供的 URL、页面文本或截图；未读取内容时标明未知 |
| 品牌与政策 | 语气、必需免责声明、不可用主张和人工审查要求 |
| 学习记录 | 已测过的角度、结果来源和时间；历史结论不自动代表当前仍有效 |

## 主张证据表

撰写前为每个重要主张建立记录：

| 主张 | 支持证据/来源 | 可安全表达的范围 | 缺失验证 | 风险 |
|---|---|---|---|---|
| 产品功能或可用性 | 产品资料、经批准的功能清单 | 证据明确覆盖的功能 | 版本、渠道或资格差异 | 功能夸大 |
| 效果/节省/速度 | 可追溯且适用的测量结果 | 适用人群、样本、时间和条件 | 统计口径或代表性 | 结果承诺 |
| 客户评价/社会证明 | 获授权且可验证的原始来源 | 经授权的原文和上下文 | 授权、时间、代表性 | 虚构或误导背书 |
| 优惠/稀缺/限时 | 当前有效的交易条款 | 明确期限和资格 | 结束时间、库存或地区 | 虚假紧迫感 |

没有支持证据的主张应删去或标成 `[NEED: evidence]`，不可用相近行业数据替代。

## 变体规划

1. 先定义一个共同的受众、优惠和主要 CTA。
2. 每条变体采用不同且可说明的动机角度，例如问题解决、使用情境、流程便利或经证明的产品差异。
3. 同一轮比较时只改变一个主要变量；标题、主文案、视觉、受众等若同时变化，必须说明无法归因到单一因素。
4. 字符限制、必填字段、素材规格和允许声明以当前平台/Tool schema 或官方规则为准，不能从旧模板推断。
5. 文案测试的受众、样本成熟度、指标和停止方式由 `experimentation-design` 补充。

## 发布前核对

- 主张是否可追溯到真实来源？
- CTA 是否对应真实、可用的优惠和目的地？
- 优惠的资格、期限、价格和限制是否准确？
- 是否包含未经授权的个人评价、比较或保证？
- 是否有虚假倒计时、夸张恐惧或误导性默认？
- 渠道/版位的字符和素材限制是否已验证？
