# 广告归因与增量测量

本 Skill 帮助解释平台、分析系统与后端/CRM 数字为何不同，并为具体业务决策选择测量方法。它补充 Wiki 的《跨平台事件、归因与增量评估》和《广告测量数据契约、对账与增量评估》。

## 分析流程

1. **先问决策。** 区分平台内日常优化、跨渠道预算分配、渠道是否产生增量、长期业务价值或数据链路排查。不同决策需要不同证据。
2. **确定结果事实来源。** 订单、财务或 CRM 系统通常用于确认已发生的业务结果；广告平台数用于说明平台依自身窗口如何分配信用。来源选择要按业务对象和数据契约验证，不把单一系统默认为所有问题的真相。
3. **对齐可比口径。** 检查日期基准与时区、点击/浏览窗口、事件定义、归因模型、币种、去重键、退款/取消、模型化转化、延迟、层级、过滤及分段。不能对齐时保留差异，不强行调平。
4. **分清归因与因果。** 平台归因和 MTA 描述已观测数据中的信用或路径；MMM 估计汇总层面的渠道贡献；合适的随机实验或准实验用于评估特定情境下的增量。任何模型都受数据覆盖、假设和设计限制。
5. **按决策成本选择方法。** 先评估可用数据、历史长度、渠道数、可随机/留出条件、决策金额和实施成本，再选方向性报表、路径分析、汇总模型或增量评估。不得只因模型复杂就认为更准确。
6. **给出有边界的结论。** 标出观察事实、解释假设、未知来源、置信度和适用期限；优先建议能区分主要解释的最小后续核查或实验。

按需加载 `references/attribution-and-incrementality.md`，用于差异对账表、方法选择和 readout 结构；涉及 MMM 可行性时加载 `references/mmm-data-readiness.md`。

## 结论边界

- 不将多个广告平台归因转化相加为业务总转化；重复主张必须与去重后的业务结果分开呈现。
- 不能把平台归因解释为增量，也不能用平台与后台的固定倍数差构造“真实 ROAS”。
- MTA 路径会受身份拼接和触点可见性影响；MMM 依赖足够的汇总历史、支出变化和模型规格；增量实验仍需检查功效、随机化、污染和外部变化。
- 自报来源、平台数字、分析系统、CRM 和财务结果各有系统性偏差；冲突本身不是某一方必然出错的证据。
- 没有对应数据源、权限或实验结果时，只能给方法建议和待验证问题，不得声称已对账、建模或完成增量测量。
- Meridian 的公开历史长度是一般经验而非硬性保证：Geo-level 通常参考至少 2 年周数据，National-level 至少 3 年；还需评估数据到参数比例、媒体变化、完整面板、控制变量与后验不确定性。少于该跨度应明确标为数据不足/方向性准备工作，不以平台 ROAS 冒充 MMM 结果。

## 执行边界

- 只使用当前 Run 中获准且来源明确的只读结果及用户提供材料。当前可使用 GA4 Tool 的 Property discovery、metadata 与聚合报告，以及广告平台实际返回的只读数据；应保留其来源、字段、时间范围和权限上下文。
- GA4 聚合结果不等于 CRM、订单、财务或 MMP 的业务事实，也不能证明事件发出、去重或归因成功。CRM、MMP 和财务数据尚无本 Skill 可用的通用连接器时，应标为待提供证据。
- 不读取凭证或用户级 PII，不执行数据导入、身份拼接或预算调整。
- 查询与写入能力以当前注册 Tool 为准；任何写操作仍须通过统一 Runtime 门禁。

## 输出要求

简洁提供：决策问题、各来源及其口径、可比性检查、差异拆解、方法选择和理由、证据限制、置信边界、建议的下一步验证。并列报告平台归因与业务结果，不伪造单一精确的“真实归因”数值。
