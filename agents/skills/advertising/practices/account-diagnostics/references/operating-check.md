# 广告账户日/周运营检查

这份清单用于把一次账户检查收敛为可审核的下一步判断。它提供分析顺序，不规定行业阈值，也不代表 Runtime 已具备对应报表或页面数据。

## 检查前

先固定账户与渠道、对比周期、账户时区、币种、目标、归因窗口、过滤条件和报表拉取时间。确认当前 Run 的只读结果完整、实时且属于预期账户。

缺少的输入标记为 `MISSING`。空结果、失败、部分分页、模拟结果和真实零值必须分开说明。来源不可用时，不得把它解释成零表现或跨渠道汇总中的零值。

## 检查顺序

按顺序检查，先找到可能解释后续变化的上游问题：

1. **支出与节奏**：支出相对预算和自身可比周期是否变化；检查预算上限、交付限制和已知账单/账户问题。没有预算或历史口径时标为 `MISSING`。
2. **流量**：展示、点击、CPC、CTR、CPM 或可用的搜索词/版位是否变化；确认报告分段和披露范围。
3. **转化与价值**：检查转化量、CVR、CPA/ROAS、价值和下游线索质量；先对齐定义、窗口和币种，再判断变化。
4. **创意**：在报告支持的情况下查看频次、点击趋势、素材年龄与花费集中度。单个指标或小样本只能触发调查，不足以直接判断疲劳。
5. **落地页**：只有已提供页面、网页快照或获准的页面结果时，检查广告承诺、页面内容、表单/结账和设备差异。未访问页面不能写成页面已故障。
6. **测量与变更**：对照可用的历史变更、事件质量、分析/CRM 结果和转化延迟。近期数据可能尚未成熟；口径冲突时先处理可信度。

当前 Tools 未提供某项来源时，明确写出缺什么以及它会怎样改变判断。不得为了填满清单而假装读取平台、分析系统、CRM 或页面。

## 决策标签

每个被检查的账户或资源可给一个当前判断：

- **HOLD**：证据没有支持改变；样本、学习状态、正常波动或转化延迟仍可能解释当前现象。写清什么新证据会改变判断。
- **FIX**：已验证的具体问题有明确修复办法。列出问题、证据和建议修复，不要把“表现下降”本身当作问题根因。
- **TEST**：存在值得验证的假设。写清唯一主要变化、主指标、护栏、规划输入和停止规则；测试设计按 `experimentation-design` 执行。
- **INVESTIGATE**：关键数据缺失、报告完整性/口径有疑问，或事实相互冲突，因此暂时不能判断表现。

`INVESTIGATE` 优先于其他表现判断：追踪或数据可信度有疑问时，先说明不确定性，不得给出绩效定论。

## 输出

简短 readout 至少包含：

1. 渠道、账户范围、周期、币种和归因窗口。
2. 当前判断及其证据。
3. 主要事实、假设和缺失数据。
4. 下一步只读核查，或供人工审核的建议草案。

没有被用户明确要求且通过 Runtime 门禁的写操作时，不修改预算、出价、定向、素材或状态。任何可能花费预算或改变投放的建议都只作为待审核草案。
