# 推荐计划：漏斗、经济性与反作弊

## 漏斗定义

每个阶段要有业务定义、唯一键、时间窗口和数据来源。建议先区分：

| 阶段 | 需要回答的问题 |
|---|---|
| 合格推荐人 | 是否达到可邀请条件，排除员工、测试账户或不合规来源的规则是什么？ |
| 发起邀请 | 邀请尝试是否由真实用户主动发起，重复发送如何去重？ |
| 邀请被接受 | 受邀人是否有可验证的接受/访问行为？ |
| 合格转化 | 激活、合格线索、首购或成交中，哪个才是本计划的目标事件？ |
| 奖励结算 | 退款、拒付、重复客户或销售取消会怎样影响结算？ |
| 长期质量 | 推荐 cohort 的留存、复购、毛利和退款是否优于可比来源？ |

不要把平台点击、邀请码使用或注册数当作漏斗末端结果。时间窗口与归属规则要在实验开始前固定，并注明跨设备、隐私限制和延迟。

## 单位经济

在同一币种和同一成熟窗口内，展示口径与假设：

- **推荐总成本** = 现金/佣金 + 折扣让利 + 履约/奖励成本 + 审核、防作弊及运营成本。
- **有效推荐 CAC** = 推荐总成本 ÷ 去重后的合格增量客户数。若增量客户数未知，只能报告归因 CAC 或情景范围。
- **首单贡献毛利** = 净收入 − 商品/服务变动成本 − 履约与支付费用 − 退款/退货成本 − 奖励成本。
- **可承受 CAC** 由客户贡献毛利与目标回收窗口决定；LTV 需要用已成熟 cohort、业务成本和保留周期支持，不能用早期预测冒充实际值。

把直接归因和增量评估并列。若用户会自然购买或本来就会被其他渠道触达，推荐归因可能高估因果增量；可按适用人群设置留出组，并记录跨组分享带来的污染。

## 反作弊检查

按业务风险和法规选择最少必要信号，不把设备指纹或敏感个人资料作为默认方案。检查重复身份、支付/地址重用、异常邀请速率、退款/拒付、奖励快速提现、优惠码公开扩散和人工误判申诉。规则需要有阈值来源、复核路径、误伤监控与数据保留边界；没有历史数据时先人工复核小规模测试。
