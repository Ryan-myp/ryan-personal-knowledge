# 推荐与联盟增长

本 Skill 用于判断推荐/联盟渠道是否适合当前业务，并设计可测量的计划。它补充 `growth-strategy` 与 `influencer-partnerships`：用户邀请熟人属于推荐计划，按成交或线索付佣属于联盟计划，创作者制作内容或授权素材属于达人合作。需要分别定义对象和结算口径。

## 设计流程

1. **确认增长目标。** 明确要获取的是有效注册、激活、合格线索、首购、复购还是高价值客户；补齐市场、商业模式、毛利、销售周期和可接受回收期。缺失时列为假设，不先承诺奖励金额。
2. **判断推荐机制是否成立。** 检查产品是否有真实的分享时机、邀请对象是否能立即理解价值、推荐人是否愿意承担声誉成本，以及分享是否给双方带来明确收益。没有自然分享场景时先验证需求，不用奖励强行制造增长。
3. **定义参与与结果事件。** 明确合格推荐人、邀请、接受、激活/成交、退款或撤销、奖励可结算的条件、归属窗口和去重键。曝光、点击、邀请码使用和注册都不能单独当作有效客户。
4. **核算单位经济。** 把现金/折扣奖励、佣金、履约、审核、防作弊和运营成本计入推荐获客成本；比较新客贡献毛利、回收期、留存/复购与基线。区分直接归因和增量贡献，优惠码被使用不自动证明该用户是增量客户。
5. **设计防滥用与体验护栏。** 检查自我推荐、重复账户、共享设备/支付方式、退款后结算、优惠码公开泄漏、奖励套利和异常批量邀请。把审核、延迟结算、封顶、申诉与合法隐私告知写入规则。
6. **设计小规模实验。** 预先写明适用人群、对照/留出方式、主指标、质量指标、成本护栏、观察窗口和停止条件。只改变一个主要机制；按成熟 cohort 对照，不用短期邀请量替代业务结果。
7. **给出决策建议。** 输出可先验证的机制、成本情景、所需字段、风险和继续/调整/停止条件。把观测事实、计算结果、假设和未知分开。

按需加载 `references/referral-unit-economics.md`，定义漏斗、增量成本与反作弊指标。

## 边界

- 仅使用用户提供的数据、当前 Run 中已授权并实际返回的 Tool 结果，或标明为示例的假设；没有 CRM/订单/推荐平台数据时不声称已验证推荐质量或增量。
- 推荐归因不是因果证明；设计留出或其他可解释的增量评估，并说明污染、跨设备和网络外溢风险。
- 本 Skill 不触发奖励、支付、外联、客户导入或联盟账户变更；不得鼓励虚假评价、误导披露或未经同意使用客户资料。
- 奖励资格、佣金、隐私告知和税务义务需按地区与法务要求复核；Skill 不代替法律意见。

## 输出

给出目标与业务条件、机制类型、合格事件与结算规则、单位经济情景、反作弊护栏、实验方案、数据缺口和停止条件。金额、比率和周期必须注明来源或假设。
