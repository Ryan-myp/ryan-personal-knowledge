# 生命周期与留存增长

本 Skill 连接广告获客与后续激活、留存、复购和贡献价值，帮助定位漏斗阶段并设计可测量的改进方案。App 获客及安装后分析优先使用 `app-growth`；广告账户内投放检查使用 `account-diagnostics`；邮件内容写作可继续交给文案能力。本 Skill 不假设 Agent 已连接 CRM、邮件发送平台或用户级分析数据。

## 分析流程

1. **确定业务结果与人群。** 说明产品/商业模式、获取来源、地区、注册/安装/首购 cohort、目标阶段和决策周期。将留存、复购、订阅续费、有效线索等结果分别定义。
2. **建立生命周期事件图。** 记录进入、关键价值行为、激活、重复价值、续费/复购、风险或退出事件的定义、时间戳、来源、去重规则和成熟延迟。事件名称存在不等于事件已正确收集。
3. **先找卡点。** 对齐每阶段分母、窗口、渠道归因和 cohort 成熟度；比较首次价值所需时间、阶段转化、留存曲线和业务价值。只有汇总数据时不推断个人行为；没有数据时给出待验证问题。
4. **区分流失类型。** 分开自愿取消、支付失败、产品未激活、使用下降、季节性/一次性购买和自然生命周期结束。预测“高风险”需要经过验证的模型或规则，不能从一两个行为直接贴标签。
5. **设计触达契约。** 为每个生命周期场景写明触发事件、适用条件、排除/抑制条件、用户同意、渠道、频率上限、消息价值、下一步动作、退出条件及失败兜底。触达要帮助用户完成真实任务，不用羞辱、隐瞒或虚假的紧迫感。
6. **设计实验和护栏。** 选择一个主要变化，定义留出组/对照、主业务指标、时间窗口、成熟度和停止规则；同步监控退订、投诉、退款、毛利、支持工单和渠道成本。短期打开/点击不代表留存提升。
7. **形成可执行建议。** 区分观测事实、解释假设和建议；如果数据不足，给出需要上传/接入的最少字段和先验证的假设，不输出伪精确的流失预测或 LTV。

按需加载 `references/lifecycle-measurement.md`，统一 cohort、阶段指标与触达评估口径。

## 边界

- 仅使用用户提供的报告/CSV、明确授权且本轮实际返回的数据；GA4 当前只提供聚合报告，不能查询个人轨迹或 CRM 状态。
- 没有邮件、CRM、推送或订阅平台 Tool 时，只提供分群和触达草案，不发送消息、不修改用户记录、不执行取消挽回或支付恢复。
- 不使用未获同意的敏感属性进行定向；对用户级数据做最小化处理，不要求把原始身份标识粘贴到对话。
- 不将相关性、平台归因或模型分数写成因果效果；保留对照、数据延迟和 cohort 未成熟等限制。

## 输出

优先给出：生命周期阶段表、瓶颈与证据质量、优先场景、触发/抑制契约、主指标与护栏、试验及停止规则、所缺数据。所有建议应说明适用对象与当前证据限制。
