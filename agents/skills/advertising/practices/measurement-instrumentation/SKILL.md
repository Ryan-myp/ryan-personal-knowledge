# 广告测量与事件契约

本 Skill 将营销和广告决策转成可审核的事件/转化测量方案，并帮助按证据定位追踪链路故障。它补充 Wiki 的《广告测量数据契约、对账与增量评估》《广告转化信号质量、CRM 回传与排障》及渠道事件规范，不代替数据工程、隐私审查或具体分析平台配置。

## 设计流程

1. **从决策反推事件。** 写明目标业务决策、关键漏斗阶段和最终业务结果，避免为了“多收数据”增加无用途事件。
2. **定义事件契约。** 每个事件注明稳定名称、业务定义、触发时机、唯一事件键、必要属性、价值/币种、来源系统、责任方、时区、允许延迟和质量验证方法。
3. **划分各层状态。** 区分业务事件发生、客户端/服务端发送、平台接收、去重、归因、报表可见及进入优化；一个状态成功不能推断下游全部成功。
4. **统一标识和命名。** 定义跨渠道 UTM 字段、允许值、大小写/分隔符、命名责任人与版本规则；将稳定业务语义与平台专属参数分开。
5. **盘点事件发送方。** 按业务事件列出浏览器、应用 SDK、服务端、GTM、CAPI/MMP、CRM 和数据仓库等发送方，标注负责系统、重试方式、唯一键与接收方。客户端和服务端并行发送时，先确认共享 event ID 的生成、透传和去重结果；不得因两个发送请求都成功就认定已去重。
6. **规划验证。** 检查触发条件、必填属性、重复与丢失、测试/生产区分、跨域/跨设备边界、延迟、退款/取消及回传状态。验证过程应记录测试条件和证据来源。
7. **检查隐私与治理。** 只收集决策所需字段，明确同意/合法依据、保留期限、访问范围和删除要求；防止原始身份信息进入日志、Prompt、Wiki 和普通分析输出。
8. **按阶段验收。** 将“业务事件发生、客户端/服务端发送、平台接收、去重/匹配、归因、报表成熟、CRM/订单确认”分别标记为通过、失败或未知。每个阶段都要有独立证据，不从上游成功推断下游成功。
9. **先定位再修复。** 按事件缺失、平台拒绝、重复、匹配弱、报表延迟、金额/币种错位分类；提出最小可复现测试、责任系统、修复项、回读证据和回滚条件。未获授权或没有工具时只给审查方案，不改外部配置。

按需加载 `references/event-measurement-contract.md`，用于事件字典与 UTM 契约；加载 `references/conversion-qa-runbook.md`，用于逐阶段 QA、失败分类和验收记录。

## 适用边界

- 若用户只想解释已经取得的广告账户报表，优先使用 `account-diagnostics`；若重点是不同来源为何数值冲突或因果归因，使用 `measurement-attribution`。
- 事件是否对某个平台可用于优化，以该平台当前官方规范、实际账户设置和已核实 Tool/数据结果为准；通用事件命名不会自动完成平台映射。
- 浏览器/服务端事件都可能重复或丢失；提供去重设计时须说明唯一键的生成方、作用范围和保留周期，不能仅凭“已发送”声称转化已记录。
- 当前 GA4 Tools 仅支持经 OAuth 授权后的 Property 发现、字段 metadata 和聚合报告查询；Search Console Tools 仅支持站点发现和有界搜索表现汇总。它们不能创建/修改事件、GTM、Pixel、CAPI、SDK 或 CRM 配置，也不提供用户级事件明细。
- 本 Skill 只提供事件设计和 QA 指导；没有对应授权与 Tool 时，不配置或执行外部 tracking。
- 广告平台事件、CRM 状态和分析平台报告之间需要分别取证。GA4 中的 key event/收入查询不等同于 CRM 确认的合格 Lead、去重订单或财务收入；缺少对应数据源时明确列为未知。
- Lead 场景应区分 `lead_submitted`、`lead_qualified`、`opportunity_created`、`customer_won` 等业务阶段（名称按企业事件契约定），选择与优化/商业决策对应的主要阶段，避免表单提交和合格线索重复计为同一种结果。
- 电商场景应定义 `view_item`、`add_to_cart`、`begin_checkout`、`purchase`、`refund` 等实际需要的阶段，校验稳定 `transaction_id`、币种、订单金额口径、退款和重复重试；不要将没有业务含义的每次页面访问当作购买。
- 浏览器或服务端测试工具的“发送成功”不等于生产事件已接收、去重、匹配和进入报表；测试流量必须与生产数据区分。
- 故障诊断以脱敏后的计数、字段存在性、状态和受控标识为证据；不得要求用户把 access token、原始邮箱/电话、设备标识或整份用户级 payload 粘贴到对话。

## 输出要求

按事件给出业务定义、业务阶段、触发、唯一键、必需属性、来源/责任人、时区与延迟、平台映射状态、发送方清单、去重规则和隐私检查。QA 结论要按链路阶段列出状态、脱敏证据、发现、责任边界、下一项验证与恢复条件，并明确标出待确认项。不得把方案草案表述成已经部署或验证。
