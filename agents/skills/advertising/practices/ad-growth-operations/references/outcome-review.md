# 优化效果记录

1. 先固定 namespace、account、资源类型和 ID，明确一个变更字段及预期值。保存成熟基线、
   指标名称/单位、币种、时区、归因天数、观察天数和冷却天数。基线来源必须说明，不能编造指标。
2. 查询是否已有相同资源字段的记录。相同建议去重；有未完成记录时先回查，不能重复调整。
3. 用户批准具体方案后，通过已有渠道 Tool 与 Runtime 执行。复盘记录不授予权限；失败或未知结果
   先回查。用 session_id、turn_id、tool_name 引用服务端审计，校验实际 live 成功及参数。
4. 使用该写 Tool 声明的 readback_tool 读取同一资源，引用读取审计和返回字段路径核验预期值。
   缺少审计、多个同名调用有歧义、范围不匹配或只有模拟输出时，保持未验证状态。
5. 到达观察窗口后，对齐等长日期窗口、指标定义、币种、时区、归因天数。结束日期之后至少等
   归因天数加七天；未成熟或数据缺失时不报改善结论。零基线不能计算相对变化率。
6. 输出基线、观察值、绝对/相对变化、数据来源和限制。用户输入的汇总指标标为用户提供，
   前后对比不等于因果或增量收益。需要因果结论时转入实验设计。
7. 冷却结束且前一轮完成复盘后，显式开启下一轮；记录保留上一轮摘要及版本轨迹。

当前记录在用户和账户范围内隔离；它协调同一用户的优化建议，不是跨用户或整个企业的写操作锁。
不支持通过此记录自动执行广告修改，也不保证所有报表结构都能自动提取指标。未知项如实标注。

展示建议使用简短表格：记录 ID、目标、建议、执行状态、回读、观察窗口、待办。用户可通过对话
查询记录和分页，不能把“proposed”写成“广告已优化”。
