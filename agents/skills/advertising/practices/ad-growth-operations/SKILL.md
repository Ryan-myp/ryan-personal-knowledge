# 广告增长运营循环

本 Skill 将一次性诊断整理成可重复的、默认只读的检查任务。它补充账户诊断、创意策略、
实验设计与通用 Agent Scheduler，不是新的 Runtime、渠道 Router 或自动投放执行器。

## 先定义循环，再安排运行

每个循环需明确：

1. **目的与决策**：保护或改善哪项业务结果；结果会触发什么人工决策。
2. **范围与证据**：可信账户/渠道范围、数据源、指标定义、时区、报表完整性和成熟度。
3. **检查频率与动作门槛**：分别说明多久检查一次，以及什么证据才值得提出动作。频率应匹配
   数据刷新、转化延迟和决策节奏，不能把“每天运行”当成“每天改预算”。
4. **检查步骤**：先验证账户与数据，再看交付/预算、流量、转化质量、创意、落地页和归因；
   只检查当前 Registry 中确实有 Tool 返回的数据。若已配置只读 GA4 / Search Console，分别读取
   获授权的 Property/站点表现；不可把自然搜索报表与广告平台口径合并，也不可将 GA4 key event
   直接称作 CRM 确认的 Lead 或订单。
5. **重复与状态处理**：定义同一问题重复出现时如何合并/冷却，以及前一次结果如何追踪。
   只有调度器 occurrence ID 不等同于业务动作幂等；需要跨运行去重但缺少持久化状态能力时，
   循环必须保持只读并报告重复项，不能重复写入。
6. **停止与升级**：列出数据缺失、超时、账户范围不明、异常波动、未知写入结果、权限不足等
   停止条件，并说明何时通知人工或暂停循环。
7. **输出**：每次报告检查时间、范围、证据来源、发现、Unknown、上次结果链接/ID（如果可读）
   和待审核建议；无变化也要简洁说明已检查与覆盖范围。

## 调度与变更边界

- 若当前 Registry 提供通用 Agent Scheduler，可用其创建定期 Prompt；定时任务仍由同一个
  Agent Runtime 运行，继承当前身份、Skills、Tools、权限和执行模式。调度器不会因 Skill
  获得新的账户访问或 Provider 权限。
- 优先调度只读检查与报告。创建定时任务只代表任务已登记，不代表未来每次查询一定成功或数据源齐全。
- 预算增加/减少、暂停/恢复、素材轮换等外部变更只能作为待审草案，除非用户对具体范围、
  条件、上限和动作明确授权，且当前 Tool 支持并通过 Runtime live、权限、确认、幂等和审计门禁。
- “低效”必须由用户认可的业务指标、成熟窗口和护栏定义。没有足够数据、回读、冷却/去重和
  回退保障时，不创建会自动执行写操作的循环。
- 失败、部分结果或执行状态未知时，不把缺失数据解释成零表现，也不重复重放有副作用的操作。

## 输出

先给循环草案：目的、读取范围、频率、动作条件、只读/写入级别、状态/去重要求、失败停止条件、
结果输出和人工确认点。缺少关键 scope、证据、冷却状态或 write gate 时，明确将其标为
**报告型循环**，不假装具备自动优化能力。

需要账户日/周检查时按需加载 `account-diagnostics` 的运营检查 reference；循环定义按需加载
`references/loop-contract.md`；实验使用 `experimentation-design`。
