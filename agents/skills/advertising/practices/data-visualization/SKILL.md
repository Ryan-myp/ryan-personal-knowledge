# 有证据的数据可视化

本 Skill 只指导如何表达已经有依据的数据。它不生成数据、不访问网页或广告账户，也不增加 Tool、权限或执行能力。图表是对数据的编码，不是填补证据空白的方式。

## 先判断请求类型

1. **流程或概念图**：表达步骤、层级或关系，不冒充定量数据；只使用已知流程和用户给出的实体。
2. **定量图表**：表达数值、比较、分布或随时间变化，必须先验证每个观测的来源、粒度和口径。
3. **示意图/创意图**：用户明确要求示意或虚构示例时可创作；清楚标明示意内容，不把它描述成真实观测或预测。

## 数据准入检查

- 每个数据点必须有来源明确的横轴和值，并确保横轴和值相互对齐；注明适用的单位、范围、日期/时区或分类口径。
- 数据只能来自用户本次提供的数据、用户明确要求复用的历史数据，或本轮成功 Tool 结果。知识库和预训练知识可以解释概念，不能代替本次观测。
- 搜索标题、摘要、片段、范围端点、最高/最低值以及互不对应的数字，不能拼成完整表格或时间序列；不能把搜索摘要拼成趋势数据。搜索摘要不是结构化数据，也不证明已读取原网页。
- 时间序列按观测粒度展示；缺失日期保留为空缺。不得跨空缺连线，不得插值、外推或凭常识补值。若使用用户明确要求的估算，说明方法并将估算与观测分开标记。
- 事实、预测、估算和示意数据必须分开。预测需要来源明确的预测序列；一个当前值或整体区间不能推出逐日预测。
- 证据不足时不要生成空白图、占位图或“看起来合理”的趋势。说明缺少哪些观测，并用短表格列出确有来源支持的数据；若没有可用观测，直接说明无法可靠绘图。

## 图表选择与呈现

- 时间趋势用有日期观测的折线图；类别比较用柱状图；分布需要足够的原始观测；流程用流程图。图形类型要匹配数据结构。
- 不要用折线连接互不连续的类别或没有顺序关系的项目；不要用面积或饼图掩盖缺失分母、重叠类别或口径不明的问题。
- 标题准确描述展示内容，不将“搜索摘要”包装成“天气趋势”或已验证结论。轴必须有单位，日期范围、来源和数据状态应清楚。
- 图表附带一句文字摘要；颜色不能成为区分数据的唯一方式，关键差异需能通过标签或文字读出。
- 展示前核对数据点数、横轴和值的对应关系、单位、范围以及标题是否超出证据。图表结论不得强于底层数据。
- 交付时检查信息层级、文字与数据标记的对比、图例和标签在目标尺寸是否可读。若实际渲染或移动端预览不可用，就标为待人工检查，不声称已完成视觉验收。

按需参考 [chart-visual-review.md](references/chart-visual-review.md) 核对图表视觉质量；结合 `web-research` 判断搜索证据粒度，或结合 `account-diagnostics` 核对广告报表口径。所有查询仍由当前 Run 中已注册且获准的 Tool 完成。
