# App Store / Google Play 页面审查清单

只依据本次 Run 已授权读取的页面、用户提供的截图/文案或明确提供的商店数据。把内容分为
**观察到的事实**、**解释假设**与**尚未核实**；不要把截图当成完整的实时商店页面。

## 页面与广告消息匹配

| 维度 | 检查问题 |
|---|---|
| 产品定位 | 名称、短描述/副标题和首屏是否说明应用解决什么问题、面向谁？ |
| 广告承诺 | 点击前的功能、价格、奖励、结果和适用条件，是否在商店页真实兑现？ |
| 视觉资产 | 图标、截图顺序、截图文案、预览视频是否展示真实功能，并适配目标市场与设备？ |
| 可信证据 | 评分、评论、开发者信息、订阅/内购和数据安全说明是否清晰；不把单条评论当总体代表？ |
| 本地化 | 广告语言、商店文本、截图和应用可用性是否匹配国家/语言；翻译质量是否有证据？ |
| 安装后连续性 | 商店强调的关键能力是否能在首次打开/引导中快速找到，避免广告、商店与产品体验断裂？ |

## 转化与实验

- 若商店访问和安装数口径均可用，明确分子、分母、时间窗、来源和系统，再讨论页面转化。
- 区分自然流量与付费来源；商店总转化变化不自动归因给某一条广告或页面元素。
- 页面建议需说明其与受众/广告主张的机制联系，提出可验证假设，而不是把最佳实践当因果结论。
- 只有确认当前商店实验能力、分流口径和流量后，才设计页面变体测试；否则提供人工审查清单。
- 商店字符限制、截图规格、审核要求、评分/评论规则以当前官方开发者资料及目标 locale 为准。

## 输出格式

```text
范围：商店、应用、国家/语言、设备、页面版本
观察事实：可从材料直接看到的内容
问题假设：广告承诺或漏斗上可能的断点
证据缺口：缺少的页面版本、商店访问/安装分母或下游 cohort
优先建议：页面/消息匹配、素材顺序、本地化或测量检查
验证方式：需要的商店实验或下游 cohort 数据；未接入时标记为待执行
```
