# 自然搜索增长与 SEO 诊断

本 Skill 用于发现自然搜索表现的可验证问题，并形成按影响、信心和修复成本排序的建议。它与
付费关键词规划不同：广告竞争指数、建议出价和广告搜索量不能直接解释自然排名难度或实际自然需求。
Google 的 AI 搜索功能仍以既有 SEO 基础为主；遵循指南也不保证抓取、收录或展示。

## 诊断流程

1. **界定站点与目标。** 确认域名/属性、业务和转化目标、国家/语言、设备、目标页面、比较
   时间窗及迁移/发布事件。对无权访问或未提供的属性不作站点级判断。
2. **盘点证据。** 标注证据是用户提供的页面/代码/日志、当前授权 Tool 返回、公开搜索摘要
   还是推断。当前网页搜索摘要不能确认页面正文、HTTP 状态、canonical、robots 或实际收录。
3. **先查可发现和可索引性。** 在有相应证据时检查 HTTP 状态与重定向、robots.txt、
   `noindex`、canonical、XML sitemap、内部链接、渲染后主要内容、重复/孤立页面及迁移映射。
   用户提供公开页面 URL 且当前 Registry 有 PageSpeed Insights Tool 时，可用其做单页
   Lighthouse 检查；报告的是该次实验室/有限字段检查，不是整站爬取或真实收录状态。
   记录样本和未检查范围；不把 sitemap 提交或 URL inspection 请求说成已收录。
4. **再查查询意图与内容。** 将真实查询（若授权 Search Console 数据可用）和目标页面按意图、
   受众、漏斗阶段映射；检查页面是否直接解决问题，信息是否独特、准确、可核验，页面间是否
   重复争抢同一意图。关键词建议不是用户实际查询或流量承诺。
5. **核对呈现与体验。** 依据提供或授权取得的页面证据，检查标题/摘要、主要内容可读性、
   结构化数据是否准确符合页面、移动可用性及真实测量的性能问题。结构化数据可帮助系统理解
   页面或符合特定搜索展示资格，不保证富结果、排名或 AI 引用。
6. **用数据判断变化。** 若存在 Search Console/分析 Tool，注明属性、日期、时区、搜索类型、
   维度、筛选条件、数据新鲜度和分页/匿名查询限制；区分 clicks、impressions、CTR 与平均位置。
   对齐站点发布、季节性、市场及转化数据，再形成根因假设。
7. **排序并验证。** 每项建议写明证据、影响机制、置信度、修复成本、负责人、回归检查方式和
   成功/停止条件。先解决阻断抓取/索引或错误信息，再做内容和信息架构实验。

需要详细检查表时按需加载 `references/organic-search-audit.md`。

## 能力边界与输出

- Google Search Console 属性数据是受授权的私有数据；只有已注册并实际成功的授权 Tool 才能读取。
- PageSpeed Insights Tool 只检查一个公开 URL，有限的 SEO 检查不能证明完整站点的 robots、
  canonical、索引状态或搜索表现。没有对应 Tool/数据时，只依据用户材料和已返回证据分析，
  不得称“已完成整站技术审计”或虚构速度、索引状态、流量和排名。
- 本 Skill 不修改网站、robots.txt、sitemap、结构化数据、内容或 Search Console 设置。
- 不承诺排名、流量或收入增长；不把短期波动直接归因于单一改动。

输出：审计范围与证据、可确认发现、推断/未知、优先级和修复建议、影响/置信度、验证方法与
需要的授权或数据。无法读取站点时，将结果明确标为基于现有材料的初步审查。
