## 一、基础问答题库（20 题）

### Java 方向（10 题）

#### 【JVM 相关】

**Q1: Java 内存模型有哪些区域？各自的作用是什么？**
- **考察点**: JVM 基础
- **期望回答**:
  - 堆：存放对象实例，GC 主要区域
  - 栈：存放局部变量、方法调用
  - 方法区：存放类信息、常量、静态变量
  - 程序计数器：记录当前执行的字节码行号
  - 本地方法栈：Native 方法服务
- **追问**: "对象什么时候会被 GC 回收？" → 引用计数 + 可达性分析
- **难度**: ⭐⭐

---

**Q2: 什么是 JVM 的垃圾回收？常见的 GC 算法有哪些？**
- **考察点**: GC 原理
- **期望回答**:
  - 标记-清除：产生碎片
  - 复制算法：浪费一半空间
  - 标记-整理：移动对象开销大
  - 分代收集：年轻代复制，老年代标记-整理
- **追问**: "如何判断对象是否可以被回收？" → 引用计数法、可达性分析
- **难度**: ⭐⭐⭐

---

**Q3: G1 GC 的特点是什么？与 CMS GC 有什么区别？**
- **考察点**: 现代 GC 理解
- **期望回答**:
  - G1: 分区管理，可预测停顿，并发标记
  - CMS: 标记-清除，并发收集，但容易产生碎片
  - G1 优先回收价值最高的 Region
- **追问**: "ZGC 相比 G1 有什么优势？" → 停顿时间 < 1ms
- **难度**: ⭐⭐⭐⭐

---

**Q4: Java 的对象创建过程是什么？对象在内存中的布局？**
- **考察点**: JVM 底层
- **期望回答**:
  - 创建过程：类加载检查 → 分配内存 → 初始化零值 → 设置对象头
  - 内存布局：对象头（Mark Word + Type Pointer）+ 实例数据 + 对齐填充
- **难度**: ⭐⭐⭐⭐

---

#### 【集合框架】

**Q5: HashMap 的实现原理是什么？JDK 7 和 JDK 8 有什么区别？**
- **考察点**: 核心数据结构
- **期望回答**:
  - 数组 + 链表 + 红黑树（JDK 8+）
  - 哈希冲突：链表存储，长度 > 8 转为红黑树
  - JDK 7: 数组 + 链表
  - JDK 8: 引入红黑树优化查询
- **追问**: "HashMap 的扩容机制是什么？" → 2 倍扩容，重新 hash
- **难度**: ⭐⭐⭐

---

**Q6: ConcurrentHashMap 如何保证线程安全？与 Hashtable 有什么区别？**
- **考察点**: 并发容器
- **期望回答**:
  - JDK 7: Segment 分段锁
  - JDK 8: CAS + synchronized + volatile
  - Hashtable: 全局 synchronized，性能差
- **追问**: "ConcurrentHashMap 的 get 操作需要加锁吗？" → 不需要，volatile 读
- **难度**: ⭐⭐⭐

---

**Q7: ArrayList 和 LinkedList 的区别？什么场景用哪个？**
- **考察点**: 基础数据结构
- **期望回答**:
  - ArrayList: 数组实现，随机访问快，插入删除慢
  - LinkedList: 双向链表，插入删除快，随机访问慢
  - 场景：频繁查询用 ArrayList，频繁插入删除用 LinkedList
- **难度**: ⭐⭐

---

**Q8: HashSet 和 TreeSet 的区别？底层实现是什么？**
- **考察点**: 集合实现
- **期望回答**:
  - HashSet: HashMap 实现，无序，O(1) 查找
  - TreeSet: 红黑树实现，有序，O(log n) 查找
- **难度**: ⭐⭐

---

#### 【并发编程】

**Q9: Java 的并发工具有哪些？synchronized 和 ReentrantLock 的区别？**
- **考察点**: 并发基础
- **期望回答**:
  - synchronized: 内置锁，自动释放，不可中断
  - ReentrantLock: 显式锁，可中断，公平锁，条件变量
- **追问**: "volatile 关键字的作用是什么？" → 可见性 + 禁止指令重排
- **难度**: ⭐⭐⭐

---

**Q10: 线程池的参数有哪些？如何确定核心线程数？**
- **考察点**: 线程池使用
- **期望回答**:
  - 参数：corePoolSize, maximumPoolSize, keepAliveTime, workQueue, threadFactory, handler
  - CPU 密集型：N+1
  - IO 密集型：2N 或 N/(1-阻塞系数)
- **追问**: "线程池的拒绝策略有哪些？" → AbortPolicy, CallerRunsPolicy, DiscardPolicy, DiscardOldestPolicy
- **难度**: ⭐⭐⭐

---

**Q11: ThreadLocal 的原理是什么？有什么使用注意事项？**
- **考察点**: 线程隔离
- **期望回答**:
  - 原理：每个线程维护一个 ThreadLocalMap，key 是 ThreadLocal 实例
  - 注意：用完要 remove，否则可能内存泄漏
- **追问**: "InheritableThreadLocal 和普通 ThreadLocal 有什么区别？" → 支持父子线程传递
- **难度**: ⭐⭐⭐

---

**Q12: CompletableFuture 如何实现异步编程？与 Future 有什么区别？**
- **考察点**: 异步编程
- **期望回答**:
  - CompletableFuture: 支持链式调用，可组合多个异步任务
  - Future: 只能阻塞获取结果，功能单一
- **追问**: "如何处理 CompletableFuture 的异常？" → exceptionally, orTimeout
- **难度**: ⭐⭐⭐

### 通用基础（7 题）

**Q21: TCP 三次握手和四次挥手的过程？为什么是三次不是两次？**
- **考察点**: 网络基础
- **期望回答**:
  - 三次握手：SYN → SYN+ACK → ACK
  - 四次挥手：FIN → ACK → FIN → ACK
  - 为什么三次：防止已失效的连接请求报文段突然传到服务端
- **追问**: "TIME_WAIT 状态的作用？" → 确保最后一个 ACK 到达
- **难度**: ⭐⭐⭐

---

**Q22: HTTP 和 HTTPS 的区别？HTTPS 的加密过程？**
- **考察点**: 网络安全
- **期望回答**:
  - HTTP: 明文传输，端口 80
  - HTTPS: SSL/TLS 加密，端口 443
  - 加密过程：客户端 hello → 服务端证书 → 协商密钥 → 加密通信
- **难度**: ⭐⭐⭐

---

**Q23: DNS 解析的过程是怎样的？CDN 的工作原理是什么？**
- **考察点**: 网络架构
- **期望回答**:
  - DNS 解析：本地 DNS → 根 DNS → 顶级域 DNS → 权威 DNS
  - CDN: 将内容缓存到边缘节点，就近访问
- **难度**: ⭐⭐⭐

---

**Q24: Linux 常用命令有哪些？如何查看进程、内存、磁盘使用情况？**
- **考察点**: 运维基础
- **期望回答**:
  - 进程：ps, top, htop
  - 内存：free, vmstat
  - 磁盘：df, du
  - 网络：netstat, ss, curl
- **难度**: ⭐⭐

---

**Q25: MySQL 索引的原理是什么？B+ 树相比 B 树有什么优势？**
- **考察点**: 数据库基础
- **期望回答**:
  - 索引原理：B+ 树，快速定位
  - B+ 树优势：所有数据在叶子节点，适合范围查询
- **追问**: "聚簇索引和非聚簇索引的区别？" → 聚簇索引数据即索引
- **难度**: ⭐⭐⭐

---

**Q26: Redis 的数据结构有哪些？各自适用什么场景？**
- **考察点**: 缓存基础
- **期望回答**:
  - String: 缓存、计数器
  - Hash: 对象存储
  - List: 消息队列
  - Set: 去重、交集
  - ZSet: 排行榜
- **难度**: ⭐⭐

---

**Q27: 什么是 CAP 定理？MySQL 和 Redis 分别满足什么一致性？**
- **考察点**: 分布式理论
- **期望回答**:
  - CAP: 一致性、可用性、分区容错性三者不可兼得
  - MySQL: 强一致（CP）
  - Redis: 高可用（AP），主从复制有延迟
- **难度**: ⭐⭐⭐⭐

### D1: 设计一个智能客服 Agent（10min）

**需求**:
> 面向电商的智能客服 Agent：
> 1. 回答订单、物流、售后问题
> 2. 调用外部工具（查询订单、发起退款）
> 3. 复杂问题转人工
> 4. 支持多轮对话

**问题**: 画出架构图，关键模块如何设计？

**期望架构**:
```
用户问题 → 意图识别 → ┌─ RAG 检索 ─┐
                    ├─ 工具调用 ─┤ → 响应生成
                    └─ 人工接管 ─┘
                          ↓
                    对话管理（多轮状态）
```

**关键模块**:
1. **意图识别**: 分类用户问题
2. **对话管理**: 维护多轮状态
3. **工具调用**: Function Calling
4. **知识检索**: RAG 检索
5. **人工接管**: 复杂问题转人工

**服务质量**:
- 意图识别准确率 > 90%
- 工具调用成功率 > 95%
- 响应时间 < 2s
- 人工接管阈值设计

**加分项**: 反馈闭环、Bad case 分析、安全护栏

### D2: 设计一个代码审查 Agent（10min）

**需求**:
> 设计一个能自动审查代码质量的 Agent：
> 1. 自动检测代码中的 Bug
> 2. 检查代码规范
> 3. 给出优化建议
> 4. 支持多种编程语言

**问题**: 如何设计这个系统？

**期望架构**:
```
Git Push → 触发 Webhook → Agent 接收 PR
    ↓
┌─────────────────────────────────┐
│  代码分析模块                    │
│  - AST 解析                      │
│  - 规则匹配                      │
│  - LLM 分析                      │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│  审查报告生成                    │
│  - Bug 等级                      │
│  - 优化建议                      │
│  - 代码示例                      │
└─────────────────────────────────┘
    ↓
GitHub Comment / PR Review
```

**关键模块**:
1. **AST 解析**: 将代码转为抽象语法树
2. **规则引擎**: 静态分析规则（ESLint/PMD 风格）
3. **LLM 分析**: 语义级代码理解
4. **报告生成**: 结构化审查结果

**加分项**:
- 提到"增量审查"（只审查变更部分）
- 提到"学习团队规范"（Fine-tune）
- 提到"自动化修复"（自动生成 Patch）

### D3: 设计一个数据分析 Agent（10min）

**需求**:
> 设计一个能通过自然语言查询数据库的 Agent：
> 1. 用户用自然语言提问
> 2. Agent 理解意图并生成 SQL
> 3. 执行 SQL 并返回结果
> 4. 可视化展示结果

**问题**: 如何设计 Text-to-SQL 系统？

**期望架构**:
```
用户问题
    ↓
┌─────────────────────────┐
│  意图理解                 │
│  - 实体识别               │
│  - schema 选择            │
└─────────────────────────┘
    ↓
┌─────────────────────────┐
│  SQL 生成                 │
│  - Prompt 构建            │
│  - LLM 生成               │
│  - SQL 校验               │
└─────────────────────────┘
    ↓
┌─────────────────────────┐
│  SQL 执行                 │
│  - 权限检查               │
│  - 执行                   │
│  - 结果格式化             │
└─────────────────────────┘
    ↓
图表展示 / 文本回答
```

**关键模块**:
1. **Schema 选择**: 从数据库元数据中选择相关表
2. **SQL 生成**: LLM 生成 SQL，需校验语法
3. **权限控制**: 只读权限，防止 DROP/DELETE
4. **结果可视化**: 自动选择合适的图表类型

**加分项**:
- 提到"COT（Chain of Thought）"
- 提到"Few-shot 示例"
- 提到"SQL 执行计划优化"

## 五、评分标准

### 基础问答评分（每题 1-5 分）

| 得分 | 标准 |
|------|------|
| 5 | 回答完整，能说出底层原理和细节 |
| 4 | 回答正确，能说出主要特点 |
| 3 | 回答基本正确，有部分遗漏 |
| 2 | 回答不完整，需要引导 |
| 1 | 基本不会，或完全错误 |

### 场景分析评分（每题 1-5 分）

| 得分 | 标准 |
|------|------|
| 5 | 方案合理，能说出优缺点和权衡 |
| 4 | 方案可行，考虑到主要问题 |
| 3 | 方案基本正确，有遗漏 |
| 2 | 方案有缺陷，需要引导 |
| 1 | 无法给出合理方案 |

### Agent 认知评分（每题 1-5 分）

| 得分 | 标准 |
|------|------|
| 5 | 理解深入，能说出细节和局限 |
| 4 | 理解正确，能说出基本概念 |
| 3 | 有一定了解，但不够深入 |
| 2 | 了解很少，需要引导 |
| 1 | 完全不了解 |

### 开放设计评分（1-5 分）

| 得分 | 标准 |
|------|------|
| 5 | 架构完整，考虑周到，有创新 |
| 4 | 架构合理，覆盖主要功能 |
| 3 | 架构基本可行，有遗漏 |
| 2 | 架构有明显缺陷 |
| 1 | 无法给出合理方案 |
