# 知识库文件质量评审标准 v1.0

## 一、评分维度（满分100分）

| 维度 | 权重 | 合格线 | 专家线 |
|------|------|--------|--------|
| 源码深度 | 30% | 70分 | 90分 |
| 真实案例 | 25% | 70分 | 90分 |
| 架构清晰度 | 20% | 70分 | 90分 |
| 代码质量 | 15% | 70分 | 90分 |
| 实用价值 | 10% | 70分 | 90分 |

---

## 二、详细标准

### 2.1 源码深度（30分）

**优秀（≥90分）**：
- 包含至少5段真实源码片段（非占位符）
- 源码来自实际项目，有完整上下文
- 代码有详细注释说明设计意图
- 包含关键算法的伪代码或实现

**合格（≥70分）**：
- 包含至少3段真实源码
- 源码可运行或有明确来源
- 有基本注释

**不合格（<70分）**：
- 使用占位符代码（如`func ExampleFunc`）
- 仅有伪代码无实际实现
- 源码与主题无关

---

### 2.2 真实案例（25分）

**优秀（≥90分）**：
- 包含3个以上生产环境真实案例
- 案例有具体问题、排查过程、解决方案
- 包含性能数据（P99延迟、吞吐等）
- 案例来自本人或团队实际经验

**合格（≥70分）**：
- 包含1-2个案例
- 案例结构完整（问题-分析-解决）
- 有基本数据支撑

**不合格（<70分）**：
- 仅有理论描述无实际案例
- 案例为虚构或泛泛而谈
- 缺少关键数据

---

### 2.3 架构清晰度（20分）

**优秀（≥90分）**：
- 包含清晰的架构图（ASCII或Mermaid）
- 章节结构完整，层次分明
- 有目录导航
- 关键概念有示意图

**合格（≥70分）**：
- 有基本架构图
- 章节结构合理
- 有目录

**不合格（<70分）**：
- 无架构图
- 结构混乱
- 无导航

---

### 2.4 代码质量（15分）

**优秀（≥90分）**：
- 代码块占比≥30%
- 所有代码有注释
- 代码风格一致
- 包含错误处理示例

**合格（≥70分）**：
- 代码块占比≥20%
- 关键代码有注释
- 基本风格一致

**不合格（<70分）**：
- 代码块占比<10%
- 代码无注释
- 风格混乱

---

### 2.5 实用价值（10分）

**优秀（≥90分）**：
- 包含配置示例（YAML/JSON）
- 有命令行使用示例
- 包含性能基准测试
- 有故障排查手册

**合格（≥70分）**：
- 有基本使用示例
- 有配置说明

**不合格（<70分）**：
- 仅有理论，无法实际操作
- 无配置或使用示例

---

## 三、评审流程

### 3.1 自评 checklist

在提交前，作者需完成以下自查：

- [ ] 所有代码片段可运行或有明确来源
- [ ] 至少包含2个生产环境案例
- [ ] 架构图清晰表达核心设计
- [ ] 代码注释覆盖率≥50%
- [ ] 包含配置示例或命令行示例
- [ ] 有性能数据或基准测试

### 3.2 同行评审

提交后需经过至少1位同行评审：

1. **技术准确性**：源码是否正确？案例是否真实？
2. **完整性**：是否覆盖关键主题？
3. **实用性**：能否指导实际工作？
4. **可读性**：结构是否清晰？

### 3.3 评审反馈

评审者需给出：
- 评分（各维度得分）
- 改进建议（具体可操作）
- 通过/不通过决定

## 四、文件分级

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| 专家级 | ≥90分 | 可直接作为技术参考 |
| 合格级 | 70-89分 | 基本可用，建议改进 |
| 不合格 | <70分 | 需要重写或大幅修改 |

## 五、评审工具

使用`file_quality_evaluator.py`进行自动化初评：

```bash
# 评估单个文件
python scripts/file_quality_evaluator.py --file path/to/file.md

# 批量评估
python scripts/file_quality_evaluator.py --batch

# 生成报告
python scripts/file_quality_evaluator.py --batch --output report.json
```
